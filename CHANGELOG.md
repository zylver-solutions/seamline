## [0.1.0] - 2026-11-10

This is the first release. All twelve published packages move from the internal `0.0.1` to `0.1.0` together and are released in lockstep. They were published to npm on 2026-11-10 from the tag `v0.1.0`, each with a provenance attestation that names this repository, `.github/workflows/release.yml` and that tag (`npm audit signatures` verifies it; see `docs/RELEASING.md`). The release workflow published under the dist-tag `next`; the registry also sets `latest` on a first publish, so both tags point at 0.1.0 and `npm install @seamline/cli` installs it. `seamline --version` and the MCP server version report `0.1.0`.

**It is an early release.** Seamline has no measured precision or recall, and it should not be relied on as a gate. The only recorded measurement (under `docs/evaluation`, the hardened draft of 2026-10-23) was made on a draft source tree, not on the code you install: it produced zero findings and detected 0 of 11 injected mutants (five missed, six UNKNOWN), with all ten detectors dormant on that scope. No passing sealed evaluation exists; it is deferred to 0.2.0. The known limits in the root README, including the tombstoning limitation, apply to this release.

**Known dependency advisory.** `minimatch@10.2.6`, reached at runtime through `@seamline/extract-code-ts` > `ts-morph` 28.0.0 > `@ts-morph/common` 0.29.0, is affected by GHSA-g3hv-75wg-m249 (CVE-2026-118764, moderate; affected `>=7.0.0 <11.0.1`, patched `>=11.0.1`). The denial of service needs `optimizationLevel >= 2`, which `@ts-morph/common` does not request, so the default configuration does not trigger it. No `ts-morph` release accepts the patched version yet. See the "Known dependency advisories" section of `SECURITY.md`.

This section summarises what is on `main`, drawn from the development history, which is squashed into this release's single public commit; the pull request numbers of that private history are not cited because they would not resolve here.

### Added

- Export profile format: an optional `packets` key (`["alignment"]`); absent means no packet may leave, and the canonical form omits it. `seamline align --profile` also requires the profile's `allow` to list `File` and `Symbol` at `internal`.
- `seamline align` and the `@seamline/align` package: a non-gating report that compares what the tracked documents claim (a runtime floor, the output formats of the CLI, which detectors work, which controls are enforced) with the implementation facts, classifies each comparison as Observed drift, Unexplained gap, Planned gap, Unknown or Resolved, and emits a versioned, redacted finding packet through an export profile that names `"packets": ["alignment"]`. Drift never changes an exit code. See ADR-0014 and `docs/design/alignment.md`.
- `seamline mcp --profile <name>` serves a real extracted store over MCP on stdio, with every tool evaluated inside the named export profile.
- `--store <dir>` selects the store directory on every command that reads or writes one.
- An extensible, temporal semantic foundation in `@seamline/core/semantic`: a profile-based engine for typed domain objects, worlds, timelines, branches and inventory, plus a bridge from the legacy code-analysis graph. Atomic authoring compositions followed.
- A dogfood regression gate (`pnpm gate:dogfood`) that compares what Seamline reports about its own repository with a reviewed baseline. The baseline now covers the reviewed regression surface (findings, the `examples/` extraction, TS/JS coverage, one lineage answer) instead of Seamline's own symbols.
- `seamline conformance <extractor-module>` and `runConformance` / `conformanceOfModule` in `@seamline/cli`: a suite an outside extractor author runs against their own extractor, under the same sandbox `seamline extract` uses, on generated fixture repositories. One PASS, FAIL or UNAVAILABLE line per property, with evidence: reads confined to the declared globs (symlinks and `..` included), no network attempt, provenance and scope ceiling, memory ceiling, time budget, and UNAVAILABLE rather than PASS on unreadable input. A property the fixtures could not exercise (nothing to pad for the memory ceiling, no bait file for the network) is UNAVAILABLE, exit 3, never PASS. Running it executes the module you name, in a sandbox that is not a boundary against a hostile extractor, and it opens only the module's directory, its `package.json`, its installed dependencies and the `node_modules` directories they are found in to the module. Offline, no new dependency; it signs and vouches for nothing. Through the project's own test harness (a representative seed, the limits and grants `seamline extract` gives them), `extract-code-ts`, `extract-data` and `extract-contracts` pass every property, and `extract-change` and `infer-join` pass all but `memory-ceiling` and `no-network`, which are UNAVAILABLE because their input is history and the run's graph, not files the suite can pad. Through `seamline conformance <module>` on a bundled extractor's module the limits are the host defaults and there is no seed, so `extract-code-ts` fails `manifest` (`timeoutS` 600 exceeds the default limit of 300) and `extract-data` is UNAVAILABLE; the two that need a host grant (`git`, the graph) cannot be run that way. See `docs/conformance.md`.
- A README for each published package.
- `@seamline/security`: a published package for the secret redactor and the untrusted-text delimiting, with a public injection corpus (`corpus/secrets.json`, `corpus/injections.json`) that tests both. The corpus holds fake credentials for every redactor rule and prompt-injection payloads for both renderers, and it can be loaded with `@seamline/security/corpus` or read as plain JSON. A conformance test runs every entry and asserts the outcome the entry states, and a second test fails when a rule has no entry (`injection-phrase`, which is opt-in, is the one `delimit` rule exempt from that per-rule coverage).
- Design records: external symbols for third-party decorators; two deferred items, a single export-profile format and non-TS/JS extractors; column-write extraction named as a deferred item.
- A documentation page per contradiction code, and a generated ontology reference (`docs/reference/ontology.md`) that `pnpm gate:ontology-ref` keeps in step with `ontology/seamline.yaml` and the extractor manifests.
- A detector can declare itself UNKNOWN from the facts alone with the optional `unknownWhen` hook, and the `Repo` node carries the write-guard props `untracedWriteCalls`, `unknownWriterTables` and `writeHooks`; a missing prop means not measured, not zero.
- `seamline why --json` and MCP `explain` gain an `unknownDetectors` array (empty when every detector ran) and a notice when a detector could not run. The key is additive; a consumer that validates the output against a closed schema will see a new key.

### Changed

- Release claims are narrowed to the recorded evaluation. The root README and the twelve package READMEs state "No measured precision or recall; do not rely on Seamline as a gate", the root README cites only the recorded figures and adds the tombstoning limitation to its known limits, and the contradictions page describes "Fires" as a capability, not a measured result. The public-release checklist splits item G8 into G8a (met) and G8b (a passing evaluation, deferred to 0.2.0).
- The redactor, entropy scanning, `RedactionError` and the `delimit` family moved from `@seamline/core` to `@seamline/security`, and the nonce-fenced `wrapUntrusted` family moved from `@seamline/mcp` to it. `@seamline/core` and `@seamline/mcp` re-export every name they exported before, so no import changes. The pack gate covers the new package and allows a `.json`-only data directory for the one package that names it.
- Both untrusted-text renderers now remove every Unicode default-ignorable code point: all variation selectors including the supplement block, the Khmer inherent vowels U+17B4 and U+17B5, the Arabic letter mark, the Hangul fillers, the combining grapheme joiner, the deprecated format characters U+206A to U+206F, the interlinear annotation characters, and the reserved ranges around the tag block. U+FE0F is removed too unless it makes an emoji (directly after a non-ASCII pictograph, or inside a keycap sequence), so it cannot split a delimiter, a role word or a heading prefix; emoji presentation sequences render unchanged. `delimit`'s `role-marker` rule also sees a turn marker behind a no-break or other non-newline space, and one that ends in a fullwidth colon. The package README lists what is still passed through ("Known limits of the neutraliser").
- Behaviour that follows from removing the tag characters and the soft hyphen, and that the four-gaps entry under Fixed does not spell out: `attemptedEscape` is now true for text that contains either, so the MCP `explain` notice that an untrusted string "contained delimiter-escape sequences" also fires for ordinary prose with a soft hyphen; the England, Scotland and Wales flag emoji (a black flag followed by tag characters) render as the plain black flag; and the zero-width joiner and non-joiner, which both renderers already removed, still break emoji ZWJ sequences and ZWNJ text. The same removal also drops the Mongolian free variation selectors, CJK ideographic variation selectors, U+FE0E, the Arabic letter mark and Hebrew right-to-left mark, the combining grapheme joiner, the joiner in Indic conjuncts and the Khmer inherent vowels from real text (no letter of modern text is removed; the Hangul fillers U+115F, U+1160, U+3164 and U+FFA0 have General_Category L, but they are placeholders, not letters used in modern Hangul text); format characters that are not default-ignorable (U+0600 to U+0605, U+06DD, U+070F, U+0890 to U+0891, U+08E2, U+110BD, U+110CD, U+13430 to U+1343F) still pass.
- **Breaking.** Every MCP tool is evaluated inside an export-profile view; nodes, edges, props and detector findings the profile does not name are never returned.
- **Breaking.** Semantic classified exports are default-deny, and classification of nested values is covered.
- **Breaking.** One canonical-name scheme for identity, and `ALIAS_OF` edges for renamed files.
- **Breaking.** The shipped `public` export profile no longer releases `firstSeenRun`, `lastSeenRun` or `deletedAt`. Under the real clock a run id is `run-<ISO timestamp>-<random>`, so every released record carried the time of the extraction that produced it and the file changed on every re-extraction of an unchanged repository. `seamline export --profile public` now writes the same bytes on two consecutive extractions, and each released node and edge loses those three keys; `seamline mcp --profile public` no longer prints them from `explain`. `team` and `audit` are unchanged and keep releasing them, a choice recorded in `docs/design/export-profile.md`.
- **Breaking.** One export profile format (`version: 1`), parsed in one place and used by `seamline export`, `seamline mcp` and the MCP server: a closed vocabulary, unknown fields rejected, provenance and untrusted text as profile fields, shipped and `exportProfiles` profiles resolved the same way, and `seamline export` applying the same engine `seamline mcp` serves reads through (so it uses the effective sensitivity). A profile in the earlier config shape is refused with a pointer to the migration in `docs/design/export-profile.md` (published at `https://github.com/zylver-solutions/seamline/blob/main/docs/design/export-profile.md`); `docs/reference/export-profile.schema.json` describes the format. Migration does not widen a profile: `fields` becomes `allowFields` name for name, a released record carries only the fields the profile names, and `firstSeenRun`, `lastSeenRun` and `deletedAt` are released only when named (a run id contains the extraction time under the real clock). The shipped profiles `public`, `team` and `audit` name every field they always released, so their output was byte-identical to before this format (the `public` profile then dropped the run ids and `deletedAt`, see the entry above). Differences for a declared profile: sensitivity is the effective level (the kind default is a floor); `props` is written as `{}` when named and nothing matched; the `--out --json` summary reports `withheld` where it reported `excluded`; `--profile team` and the other shipped names now work with `export`; and an absent `exportProfiles` key no longer injects the starter profile. Two relations are checked when a profile loads: a profile that allows props (an `allowProps` or `allowEdgeProps` entry that is `'*'` or a non-empty list) must name `props` in `allowFields`, and `includeUntrusted: true` needs `untrusted` in `allowFields`, so a file never drops props an agent is served and untrusted text never leaves without its marker. On MCP, `allowFields` governs the location fields and the lifecycle fields only: the tools always print `id`, `kind`, `name`, `src`, `dst`, `untrusted`, `provenance`, `confidence`, `sensitivity` and the props the profile names.
- For a declared profile, `seamline export` writes the keys of each released record in a fixed canonical order (`id`, `kind`, `name`, ...; see `RECORD_FIELDS`), where it wrote them alphabetically. The content is equal, but a committed export gets a one-time reorder diff.
- **The `init` starter profile is renamed `public-inventory` to `structure`, and it now releases something.** The old starter named its kinds at `public`, above which they always sit (`internal`), so it released nothing. `structure` names `internal` and releases the file layout and import graph (paths, the module tree, `CONTAINS` and `IMPORTS` edges, extracted facts only, no run ids). The name no longer says "public", and its description and the output of `seamline init` say it is internal-level. Rename any `--profile public-inventory` in scripts.
- **Package API changes** (the packages had no earlier release; this list is the difference between the public entry points of `main` and this change). `@seamline/core`: removed `assertIsAllowList` (replaced by `parseExportProfile`), `OPTIONAL_NODE_FIELDS` and `OptionalNodeField` (replaced by `RECORD_FIELDS` and `RecordField`); added `parseExportProfile`, `parseDeclaredProfiles`, `profileNames`, `EXPORT_PROFILE_VERSION`, `EXPORT_PROFILE_FIELDS`, `RECORD_FIELDS`, `LOCATION_FIELDS`, `LIFECYCLE_FIELDS`, `PRE_VERSION_FIELDS`, `PROFILE_NAME_PATTERN`, `PROFILE_DESCRIPTION_MAX`, `FORMAT_DOC_URL` and the types `RecordField`, `ReleasedNode` and `ReleasedEdge`; reshaped `ExportProfile` (it now requires `version`, `allowProvenance` and `includeUntrusted`, and `allowFields` is the closed record-field list), `getProfile(name, declared?)` (own properties only, so `constructor` and `__proto__` are no longer profiles), `ExportResult` (`nodes` and `edges` are `ReleasedNode[]` and `ReleasedEdge[]`, carrying only the selected fields) and `WITHHOLD_REASONS` (gains `provenance-not-allowed` and `untrusted-not-allowed`); `applyProfile` and `profileView` keep their signatures and now apply the provenance and untrusted decisions and the record-field selection. `@seamline/mcp`: nothing added or removed; `createServer` refuses a profile without `version` (and any profile the parser refuses), the tool context's `Released` gains `field(name)`, and `explain` prints the lifecycle fields only when the profile names them. `@seamline/cli`: removed its own `applyProfile`; added `exportThrough` and `resolveProfile`; `ExportProfile` is now an alias of core's type; `ExportReport` is reshaped (`excluded` is `withheld`, in the `--out --json` summary too, and `nodes` and `edges` are `ReleasedNode[]` and `ReleasedEdge[]`).
- `typescript` is an optional peer dependency of `@seamline/extract-contracts`.
- The three duplicate in-memory `GraphView` test doubles share one implementation.
- Documentation was reconciled with the code: output formats, dormant detectors and the Node floor; the public-release checklist; the leak sweep; governance placeholders; the aspirational state, kept inside the v3 cut.
- Toolchain and dependency updates: TypeScript 5.9.3 to 6.0.3, ESLint 9 to 10, `@types/node`, `fast-check`, `yaml` 2.9.0 to 2.9.1, `pnpm/action-setup` 6.0.10 to 6.1.0, and the dev-toolchain group. `packageManager` is pinned to a pnpm 10.x release that supports the Node floor.

### Fixed

- `@seamline/extract-code-ts`: tsconfig coverage is reported and only the files actually read are claimed; tsconfig projects the root graph does not reference are also loaded; a router call is extracted as a route only on a server receiver; `IMPORTS` facts no longer depend on statement order.
- `@seamline/extract-contracts`: incomplete Zod composition coverage is rejected.
- `@seamline/extract-data`: ClickHouse DDL is read by ClickHouse rules when a statement carries ClickHouse-only evidence: a column is nullable only when its type is `Nullable(T)`, wrapper types normalize to the type underneath, aggregate-state types abstain from type comparison, and columns with no default are recorded as defaulted. Standard-SQL DDL is unchanged.
- `@seamline/extract-data`: migrations that share a version in different directories no longer share an id. Every one of them is qualified by its directory (`0001_init~a~migrations`) with a separator that `makeNodeId` accepts; the qualifier is a function of the set of files, not of discovery order, and a version held by one file keeps its bare id. Migration ids are minted through `makeNodeId`, and `migrationName` and `makeNodeId` now agree on what a Migration name is. A migration version outside the id alphabet is sanitised (each other character becomes `_`) and reported as a diagnostic, so a single migration whose version is, say, `002 (copy)` changes id against earlier releases (`Migration:002 (copy)` becomes `Migration:002__copy_`), as do the `MIGRATED_BY` edge keys that end at it.
- `@seamline/infer-join`: validators are recognised from extracted facts, not name suffixes; a schema value's members come from its lowered contract.
- `@seamline/cli`: cross-extractor last-writer-wins node upserts are gone.
- Store: scope selectors are evaluated exactly, so vanished nodes are tombstoned; edge tombstoning is confined to the run's authoritative selector.
- `@seamline/core/semantic`: disclosure for snapshot, query and export is value-aware.
- The dogfood gate's byte-exact baseline excludes `@seamline/extract-change`.
- Release: npm provenance verification, with `@seamline/cli` kept as the published name.

### Security

- MCP: internal-error detail stays server-side, `viaPath` is checked strictly, and the export profile is pinned as a deep-frozen copy at server start.
- The extract pipeline writes through the redactor as its sole writer.
- The redactor never rewrites identity or repository paths.
- git started from a command that reads an untrusted checkout no longer runs a program the repository's own configuration names. The CLI process, `seamline align` and `@seamline/extract-change` previously cleared only the system and global git configuration, so a repository's `.git/config` and `.gitattributes` could still start `core.fsmonitor`, clean, smudge and process filters, textconv, external diff and merge drivers, hooks or `gpg.program` as the user, outside the sandbox. Each of the three now starts git through one function that overrides those settings, neutralises every driver the effective configuration defines, adds `--no-ext-diff --no-textconv` to patch-producing subcommands and refuses a repository whose driver names it cannot override or that defines more than 512 drivers. A clean filter never runs, so a file a filter would normalise is reported as changed (over-reports, never misses). `THREATMODEL.md` records the closed limit.
- Untrusted-text delimiting closes four gaps found by the new injection corpus: neither renderer stripped the Unicode tag characters (U+E0000 block, which write invisible ASCII a model can read); `wrapUntrusted` did not strip the soft hyphen; and `delimit` did not treat a lone carriage return or a Unicode line separator as a line break, so a turn marker after one of them escaped the `role-marker` rule.
- `delimit` neutralises in linear time. The `fence-sentinel` pattern backtracked over runs of whitespace (4,000 spaces took 45 seconds, and the cost grew with the cube of the run), so a field with a few thousand spaces or blank lines stalled a consumer. The rule now finds the sentinel with a linear pattern and extends each match to its leading brackets and whitespace by hand; it matches exactly what the old pattern matched (checked on generated input), and a test fails in seconds, not minutes, if it becomes slow again. The cost was already present before the delimiting moved into `@seamline/security`.
- `@seamline/extract-contracts` no longer leaks absolute local paths into diagnostics.
- `@seamline/extract-change`: the README and design table said rename detection used `git diff -M` through simple-git; it uses `git log --find-renames` in a plain git subprocess.
- CLI text output escapes repository-controlled text: names, paths, findings, diagnostics, refs and error messages no longer reach the terminal with escape sequences, C0 or C1 controls, DEL, bidirectional overrides, zero-width characters or line separators, so a directory named with `ESC[31m` or `ESC]0;title BEL` cannot recolour the screen, set the window title or forge a line. Each is shown in escaped form (`\x1b`, `\u202e`). `--json`, exports, packets and the MCP server are unchanged. The helper is `printable` in `@seamline/security`.

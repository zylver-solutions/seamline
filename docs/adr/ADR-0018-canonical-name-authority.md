# ADR-0018: authority confined to a known contract identity

- Status: accepted. The coordinated selector/store/SIF foundation is merged. Producer adoption and release evidence remain separate.
- Date: 2026-10-23
- Named consumer: the local validated-write producer and X7 (`docs/design/x7-upper-length.md`).
- Forced by: the mixed supported/opaque retention finding in the X7 producer draft of 2026-10-23, at `packages/extract-contracts/src/write-extract.ts`, around line 122 of that draft. A filename-wide claim can retire an unproved contract beside a proved contract. Recognizing more parser spellings does not establish absence of every opaque binding.

## Problem

A handler can completely prove `goodSchema` while another local `schema` becomes opaque. The latter may flow through a result alias, property reads or a helper instead of a recognized parser call. A successful proof of `goodSchema` does not authorize deletion of the old `schema` facts. Whole-file authority confuses those two conclusions.

Withholding the file preserves the unknown facts, but current X7 authority also rejects the known facts in that file. We need authority over the complete, known contract identity and its property names. This is a narrower claim than authority over every contract a file might declare.

## Decision

Keep `AuthoritativeScope`'s existing shape. Coordinate a separate core/protocol implementation before the X7 producer change uses this selector. The SIF compatibility change below must have its own coordinated contract review, outside the X7 producer change. No new node kind, edge kind, query operation, annotation or external package is introduced. Producers may declare an internal dependency on the existing Apache-2.0 core workspace package to use its reviewed codec and structural guards, with the normal license gate. Existing security-corpus test fixtures may use that existing workspace package as a development dependency; this grants no new external runtime dependency or public export.

A canonical selector starts with the exact reserved prefix `/@canonical/v1/`. Its suffix is lowercase hexadecimal for the UTF-8 bytes of compact canonical JSON with exactly these keys, in this order:

```json
{"path":"src/form.ts","rules":[["exact","abc"],["prefix","abc#/"]]}
```

`path` is one literal repo-relative POSIX source path, never a glob. It must have no leading slash, backslash, control character, empty, dot or parent segment. `rules` is a nonempty array of two-element arrays. The first element is `exact` or `prefix`; the second is a nonempty literal canonical name or prefix without control characters. No wildcard, exclusion, brace expansion, expression or normalization is interpreted. Rules are sorted by operation then UTF-8 byte order of their value, with duplicates removed by the producer. Decoding must validate the exact object/tuple shape, strict UTF-8 and canonical round-trip encoding. Every decoded path and rule string must contain only Unicode scalar values: reject unpaired UTF-16 surrogates, including JSON-escaped ones. No Unicode normalization is performed. Alternate encodings, unknown keys or versions are rejected.

The canonical name is parsed from `node.id`, not the display `name`. A match also requires the node's literal `path` to equal the confined source path, its parsed repository to equal the active run repository, and its parsed kind to agree with its stored kind and the claim. Paths confine authority; they supply no identity segment. An absent or malformed id or path cannot match. Claims with no node kinds cannot use this mode: infer-join's existing edge labels keep their semantics. Invalid metadata is an error, never a broad fallback.

The leading slash forces an earlier path compiler to reject this encoding when compilation occurs. It does not itself protect older readers reopening stored metadata. Implementation must also establish both compatibility barriers:

- Advance SQLite's persisted schema/semantics version from 1 to 2. In one transaction, replace `authoritative_scopes` with `authority_claims_v2`, whose primary key is `(run_id, extractor, claim_index)`. `claim_index` is a nonnegative metadata ordinal within that result's ordered claims, never a fact identity. Keep the scope, kinds and selector columns, corresponding scope index and non-cascading foreign key to `extractor_results(run_id, extractor)`; orphan claims are forbidden. This permits several kind-specific claims for the same extractor/scope. Reconstruct and preserve their order by ordinal. Migrate every old row in deterministic scope order, preserving its meaning, all runs, facts, edges, stamps and tombstones; validate old rows as legacy path claims. Commit the version marker only with the full migration. Failure rolls back. Retain `authoritative_scopes` only as an empty write-refusal guard table with the legacy columns and an unconditional `CHECK(0)` constraint, never as a view of new claims. New code reads/writes only `authority_claims_v2`. Version-2 open validation must require the guard and its refusal constraint. This survives old bootstrap code that executes CREATE TABLE IF NOT EXISTS before checking the version marker: it cannot recreate a writable legacy table. An already-open old reader sees no declared scopes and reports UNAVAILABLE; an old finalization that declares a scope fails its scope insert and rolls back that transaction. The guard prevents scope certification, not older raw fact upserts; an unfinished or empty-authority old run must not make those facts current. Actual pre-change code must reject a version-2 store at open before exposing scope status.
- Coordinate SIF version 2 before writing canonical claims. Its mandatory first line is the literal ASCII framing line `seamline-sif/2.0.0`, followed by LF. It is intentionally not JSON. Old strict core readers and the old permissive CLI reader both call JSON.parse and must reject this line before evaluation; an unknown JSON record type alone is insufficient because that CLI silently skips it. The record body remains the existing `SifLine` JSON-lines union. Coordinate `SIF_VERSION` and public framing changes in their own protocol change outside the X7 producer change. Updated writers, including worker transport, emit this header deterministically. New readers may accept headerless version-1 streams only with old path claims; canonical claims require the version-2 framing context. Standalone line readers default to legacy semantics without that context. Duplicate, late or unknown framing fails closed. Import validation is atomic with respect to finalization and tombstoning.

A passive old parser preserving a selector string is not a successful compatibility check. Test actual pre-change SQLite reopen and SIF evaluation paths. Unsupported versions or semantics cannot establish PASS or an examined negative. This record grants permission to coordinate that protocol change; it does not authorize silently modifying the frozen seam inside the X7 producer change.

Before splitting or decoding selector bodies, enforce a cumulative 65,536-byte UTF-8 budget across the run's encoded canonical selectors. The hex envelope then bounds decoded JSON to less than 32,768 bytes. Check each bounded decoded array's length before iterating or copying it; the aggregate rule limit is 2,048 across the run. No regex expansion or decoded-rule buffer is allocated before the encoded-byte check. Many small claims and oversized malformed claims must be tested. Producer exhaustion returns a non-PASS result for the affected extractor; it cannot fall back to filename authority. Existing read, resolution, syntax, process memory and timeout limits stay unchanged.

## Nodes, edges and persistence

Node coverage is the conjunction of claimed kind, active repository, literal source path and literal canonical-name matching. A prefix comparison preserves punctuation and Unicode; `abc#/` cannot match `abcd#/`. An exact rule cannot select descendants. SQL and JavaScript must agree, including a stored kind disagreeing with the id.

An edge must belong to the claim's scope, and both endpoint ids must belong to the active run repository. Its canonical anchor is its source endpoint when that endpoint's parsed kind is named by the claim; otherwise its destination endpoint when that kind is named; otherwise there is no anchor. The anchor's stored node must exist, its stored kind must agree with its id, its source path must equal the confined path, and its canonical name must match. Tombstoned endpoint records still exist and can anchor deletion; a missing or malformed endpoint cannot. Existing path anchors and labels do not change. Foreign-scope and foreign-repository edges remain untouched.

SQLite sweep, in-memory merge, manifest/result validation and CLI/MCP current-observation checks must share these semantics and validate aggregate limits. SQL values remain bound parameters; no raw query surface is added. Tombstones, run stamps and deterministic retry behavior stay unchanged.

The encoded claims travel through existing SIF run results. Export, import and reopened-store evaluation must preserve them and their fail-closed behavior. A freshly upserted stamp alone, including a repeated deterministic run id, remains insufficient to certify a retained unknown fact.

## Producer policy for the named consumer

Every currently present or opaque local write-handler file stays outside filename-wide deletion authority for contracts. A complete known binding may add a canonical claim only after all existing identity-collision withholding and source-proof checks. It must have a completely read property-name set; unknown schema composition cannot authorize a descendant prefix merely because one field was recognized.

For each eligible known contract, emit two kind-specific claims under `contracts`, confined to its proved source path: a `Contract` claim with its exact canonical name, and a `SchemaProperty` claim with the literal prefix of that name followed by `#/`. Never put both rules under both kinds. Build them after withholding, in deterministic order. A failed, unavailable, ambiguous or wholly unsupported binding supplies no canonical claim. Exact identity collisions remain withheld, including when one declaration becomes opaque. Before using a property prefix, prove ownership of that canonical family: inspect known and reserved/withheld contract names for `A#/` overlap and withhold every overlapping family. If possible collisions or overlap cannot be excluded within the confined source path, do not emit the canonical claim. A partial inventory of successfully proved candidates is insufficient. Do not rename a legacy contract to avoid the ambiguity. Known legacy contracts in the same file may use equivalent claims only when their complete name sets are proved; otherwise they remain outside current authority.

Thus the known `goodSchema` facts can be current and their removed properties can be tombstoned, while the different unknown `schema` identity remains live outside authority. If the handler or file disappears under a complete ordinary path claim, its older facts may be retired by that path claim. Partial source coverage still never proves an unobserved identity absent.

This amendment does not weaken parser, field-forwarding, client-source or collision guards. It does not make the hardened Umami target supported. The exact real parent conflict, examined fixed negative, reviewer councils, baseline review and independent evaluation remain required by the X7 design.

## Required acceptance before implementation merge

1. Prove old/new selector, SQLite and SIF compatibility using actual pre-change implementations. Verify transactional version-1 store migration with multiple same-scope claims and preserved legacy meaning; the ordered interaction open old connection, migrate with new code, attempt old reopen and verify rejection, then exercise scope queries and scoped finalization through the original old connection. It must report UNAVAILABLE and refuse that finalization transaction without changing new claims or facts in that transaction, even after the failed reopen. Also test an old same-id restart followed by empty-authority finalization and old raw upserts: none may leave reusable stale claims or establish current canonical authority; actual old core and CLI refusal of version-2 framing before evaluation; atomic import and non-PASS on unsupported metadata. Test budgets before allocation, many small claims and oversized malformed input.
2. Compare actual SQLite sweeps and the JavaScript matcher on generated exact/prefix cases, Unicode and punctuation, plus literal source-path confinement, a canonical-looking filename that cannot substitute for identity, mismatched id/stored kinds, same-name nodes/edges from another repository, escaped lone surrogates and distinct canonically equivalent Unicode spellings without normalization.
3. In one file, prove contract A while previously supported contract B becomes opaque through direct calls, immutable aliases, mutable assignments, property reads and helper forwarding. A must remain current; B and its edges must remain retained outside authority, even on a same-id retry. No alternate Legacy PASS may substitute for these assertions. Include an exact duplicate where one declaration becomes opaque, and a distinct legacy contract named `A#/B` with its properties; claims for A must not retire that family.
4. Remove a field from A while keeping its complete shape. Its old property and owned edges must be tombstoned. Retain B and foreign-scope edges. Then remove the handler/file under a complete path claim and prove ordinary forgetting still works.
5. Round-trip SIF, reopen SQLite and exercise `check`, `why` and MCP currentness. Missing, failed, unfinished, malformed or old-reader metadata never establishes a positive result or an examined negative.
6. Keep path-free eligible-move identities and deterministic bytes. Mutate canonical-name selection to filename selection, widen exact to prefix, remove the separator or kinds guard, broaden edge ownership and omit canonical currentness individually; meaningful outcome assertions must kill each mutation.
7. Run the standard full verification, leak scans and publication dry-run on the exact candidate, fresh source councils and green CI. Baseline changes stay in their own reviewed PR.

## Alternatives

More syntax-specific uncertainty checks miss equivalent source forms and are rejected as the authority boundary. Treating UNKNOWN as an examined negative is rejected. Giving a known contract the whole filename is rejected. A new observation manifest would require broader state and SIF coordination; the existing selector slot expresses this narrower authority. A format/open barrier is nevertheless necessary: the absolute selector prefix alone is insufficient for reopened older readers. The SIF contract change is coordinated separately before feature use. Hashes, source paths and generated ids cannot replace ADR-0017 identity inputs.

The cost is another bounded selector form and coordinated consumers. The shared foundation is implemented on main; the X7 producer change must still prove producer adoption, mixed-contract retention and every acceptance requirement above before merge. Foundation verification does not establish that its real-source or qualification blockers are resolved.

# Public release checklist

**Status on 2026-11-10: released, with open items.** The repository became public on 2026-11-09, and version 0.1.0 of the twelve `@seamline` packages was published to npm on 2026-11-10 with provenance, from tag `v0.1.0`. Still open: B8, C6, E5, F6, G8b, H1, H3, H4 and H5, and D4 needs a regeneration. Each is described at its item, and the table at the end summarises every section. Items marked "awaiting a maintainer" need a person's statement or action and cannot be closed from evidence alone.

**How to read the older entries.** Entries dated before 2026-11-09 were written while the repository was private and are kept as written. Some refer to things an outside reader cannot see: a private issue tracker (identifiers of the form `seamline-` plus three characters), parallel work that was in progress at the time, and "the operator", which means the maintainer who decided on and performed the release. None of those references is needed to check an item. Notes headed "Update 2026-11-10" were added after the release and say what was verified on that date and how.

**Status recorded on 2026-08-30 (superseded by the status above): NOT READY. All code-, docs-, and config-verifiable work is done as of 2026-08-30. What remains is entirely human/operator action (real mailboxes, GitHub org settings, npm account, a real PR, one written provenance sign-off, and one deliberately-deferred git-history decision).**

This repository is the first public repository this organization has ever released, so there was no in-house precedent to copy and no muscle memory to rely on. Everything below is therefore written to be _checkable_: each item names a command to run or a fact to observe, not a feeling to have.

**How to use this.** Work top to bottom. An item is done when the stated check produces the stated result, and a person has initialled it. "It looks fine" does not close an item. Two of the three sweeps are automated:

```bash
node scripts/internal-leak-scan.mjs     # A and B: internal material
node scripts/license-gate.mjs --notices # D: dependency licensing
node scripts/determinism-gate.mjs       # G: the reproducibility claim in the README
```

Nothing is published while any of the three exits non-zero. As of 2026-08-30 all three exit `0`.

**Update 2026-11-10.** On `main` at `fad96ba`, `node scripts/internal-leak-scan.mjs --publish` and `node scripts/license-gate.mjs` both exit `0` when run locally, and all three ran green in [CI on that commit](https://github.com/zylver-solutions/seamline/actions/runs/42705537823). On the tagged commit, all three passed in the `Re-verify the tagged tree` job of the [release run](https://github.com/zylver-solutions/seamline/actions/runs/42716095820) on 2026-11-09, before anything was published.

**One rule that outranks the rest:** if a check fails, fix the repository. Do not narrow the check. A scan pattern relaxed to get a green run is how internal material ships. (One narrow exception was made on 2026-08-30: `scripts/internal-leak-scan.mjs`'s L2 rule now excludes the literal `/home/example/`, the canonical fictional path used by this repo's own negative-path-rejection test fixtures, mirroring the pre-existing `dev` exclusion in the same rule's Windows-path branch. Every other `/home/<user>/` path still flags.)

**Resolved finding, was not part of this checklist's original scope:** an F/G audit pass on 2026-08-30 found that the Redactor (now `packages/security/src/redactor.ts`, in `@seamline/security`) was fully implemented and tested in isolation but never called by the extract pipeline: `packages/cli/src/commands/extract.ts` wrote extractor output straight to the store, and THREATMODEL.md's control C3 described protection that did not exist in the shipped code. Tracked as `seamline-wcn` (P1) and closed on 2026-08-30: `wrapWithRedaction()` is now wired at the one production `SqliteStore` construction site (`packages/cli/src/wiring.ts`'s `sqliteStorePort()`, per ADR-0011), covers both the store and the `.sif` snapshot, and `packages/core/src/security/redacting-store.test.ts` proves the property against a real `SqliteStore`, not a fake.

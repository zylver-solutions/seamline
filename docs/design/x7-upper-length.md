Status: accepted design for the X7 validated-write producer; a bounded implementation shipped in 0.1.0 (producer: `packages/extract-contracts/src/write-*.ts`; detector: `packages/contradictions/src/detectors/x7-validator-divergence.ts`; status checked 2026-11-10). Independent source reviews, full repository gates and independent qualification remain required. It narrows the X7 part of `real-world-inputs.md` section 5.5; X3 and other X7 dimensions remain deferred.

## Observable conflict

Report only a live fact Column with an explicitly extracted finite nonnegative integer maxLength and a live fact SchemaProperty with all of these producer facts:

- `lengthUpperState` is `unbounded`.
- `valueRole` is `validated-write-input`.
- `storageModel` and `storageField` identify a uniquely resolved Prisma model and scalar field.
- `writeBindingComplete` is true for that property, including successful parsing and unchanged forwarding.

An unbounded state means the supported validator accepts strings of arbitrarily large length on that field. It must be established by positive examination of the supported syntax. A missing prop, another known constraint, an empty constraints map, or a missing source file is unknown. Requiredness and nullability never establish length coverage.

A property with an extracted upper bound is outside this X7 admission, whether it is equal, stricter or looser than storage. The stricter case is a normal input boundary. Both-stated unequal bounds remain X3's deferred subject. Response schemas and unbound validators cannot fire this rule.

The claim states that the validated input permits strings longer than the declared storage bound along the extracted write binding. It does not promise a database error, HTTP 500, exploit, reachability for every caller or an executed request.

## Length producer

Initially admit Zod string chains only. Emit `lengthUpperState` as `bounded`, `unbounded` or `unknown` for each property. `bounded` requires one supported literal nonnegative integer max or length operation. Plain string, optionally wrapped in supported optional/nullable/nullish operations, is unbounded. Other operations are initially unknown, including min, enum, regex, coercion, default, catch, transforms, pipes, refinements, intersections and unions. This deliberately small grammar avoids claiming that an unread rule accepts long strings. An unknown operation anywhere on an ancestor object also prevents unbounded credit for its descendants.

Ordinary body proofs and GET-copy proofs both require the reviewed Zod 4.3.6 artifact and its full lock integrity. Registry versions, ranges and tags remain valid declaration forms when the matching importer resolves to that reviewed artifact. Missing metadata, customized resolutions and unreviewed resolved versions withhold provenance. Namespace spelling alone cannot establish library behavior. Private validator internals and reflection that can expose shared constructors withhold the proof, including outside a GET-copy branch. Runtime imports and loads require inspected source or an existing effect summary before any unrelated-basename exclusion; metadata-only native loads retain their complete readonly-use checks.

The source resolver inspects the plain `tsconfig.json` or `jsconfig.json` fallback. If both exist, their resolver maps must agree; an unresolved selection cannot certify a library origin or caller exclusion. Complete-inventory origin checks only establish that an imported file belongs to the safety walk. They follow no imported declaration and consume that walk's existing inventory, file, memory and time bounds. Actual declaration and binding traversal retains its module/resolution budgets and complete memoized charges. Names-only collision reservations may recover declared lineage after an invocation or effects refusal, but carry an explicit reservation purpose, no client proof, no admitted field and no currentness authority.

Additional library-effect coverage is proposed in [library effect certificates](library-effect-certificates.md). That proposal grants no source permission until its design is accepted and its implementation proves the unchanged acceptance below. Note (2026-11-10): that design is accepted and its verifier is implemented in 0.1.0 (`packages/extract-contracts/src/write-effect-*.ts`); the acceptance below is still unmet.

Dynamic or invalid max/length arguments, repeated bounds, unsupported aliases, shadowed Zod imports, mutation, escapes, incomplete shapes, cycles, syntax errors and exhausted work limits produce unknown or withhold the affected contract. Never turn them into unbounded. Later grammar expansion needs its own tests and review. Existing extracted maxLength remains a stated fact; this new state does not retroactively certify it as an effective bound.

The scalar state is emitted by the Zod producer. OpenAPI and JSON Schema properties receive no complete-length credit in this pass. The ontology contract remains unchanged.

## Scoped declarations and natural identity

Read a function-local const schema only when the complete write binding below is proved. Initially support a direct const declaration in a named function's body, with no nested block shadowing. Existing top-level schema identities remain unchanged. Do not reinterpret an arbitrary local object as a validator.

For a newly admitted local schema, the natural key is the JSON tuple of the declared package name, lexical named declaration chain including the schema binding, resolved persistence-wrapper package and declaration chain, and declared Prisma model name. The Contract name is `validated-write:` followed by lowercase hexadecimal encoding of the canonical tuple JSON's UTF-8 bytes. This is reversible identifier encoding, not hashing; existing canonical-name validators remain unchanged. A SchemaProperty keeps the existing `(contract, JSON pointer)` identity. JSON separates segments; the subsequent reversible byte encoding keeps scoped package slashes and JSON escapes out of the canonical identifier. Round-trip recovery must reproduce the exact tuple without inventing names.

Every input comes from a source declaration or a proved binding. Paths, route directories, file stems, source offsets, insertion order, ordinals and content hashes are excluded. A file move preserving these inputs preserves the non-File ids. Changing a listed key input changes the natural key and is disclosed in ADR-0016. Changing a forwarded field or write operation need not change those inputs. A schema reaching more than one storage model is withheld in this first implementation. If two distinct declarations produce the same key, withhold every conflicting contract and its properties, diagnose the collision, and exclude all affected source files from authoritative deletion. Never select a first winner or silently union two schemas.

[ADR-0017](../adr/ADR-0017-validated-write-contract-identity.md) specifies the permitted Contract inputs for this producer; its implementation must add exact minting-source references and conformance tests without rewriting the accepted ADR-0016 table. The implementation emits this key; its minting functions and tests are recorded in ADR-0017.

## Bounded source analysis

The contracts extractor owns the new facts. It reads TypeScript syntax and declared Prisma generator/model metadata using repository-confined capped reads. It adds prisma, js and jsx to its manifest only with the implementation and regenerates the ontology reference then. JavaScript is parsed for reference and cache-write completeness; this does not admit JavaScript Zod contracts by itself. It executes no source, generated client, module initializer, install hook, SQL or upstream test. It opens no network connection. It reads no generated output to make an unresolved declaration appear installed.

Resolve relative imports, re-export barrels and tsconfig path aliases within the repository. Bare external imports without an explicitly reviewed library summary, symlink escapes, unknown dynamic imports, ambiguous exports and missing files stop the proof. Recognize a generated Prisma client import only when its resolved source location agrees with a parsed in-repo Prisma generator output and the named model exists in that same schema. A variable spelling or a Prisma-shaped method name alone is insufficient.

Initially support two wrapper boundaries: one parsing helper and one persistence helper. A summary is proved from its source body, never its name. Parsing recognizes a schema parameter's safeParse call, its success discriminator, and the returned parsed value. The caller must guard the returned error branch before using that value. Preserve request-method conditions: a helper returning parsed query on GET and parsed body otherwise supplies a body proof only where the caller's method is statically non-GET. The initial server-method rule recognizes a direct exported method declaration in an App Router route.ts file under app or src/app, with Next 16.2.6 declared and locked in that package. This is the [documented Next method-export contract](https://nextjs.org/docs/app/api-reference/file-conventions/route). Re-exported handlers, method aliases, unsupported framework versions, custom page-extension configuration and ambiguous package ownership withhold. A Next TypeScript configuration may name only the default tsconfig.json; a custom selected configuration must not bypass the resolver and artifact checks by hiding its aliases in another file. The file convention establishes routing eligibility only; it supplies neither a domain name nor an identity segment. An ordinary function named POST is insufficient.

For the admitted parser shape, error starts undefined. A failed schema.safeParse assigns a callable error; a successful non-GET branch assigns result.data to body. Authentication may add an error but must not clear it or replace body. The returned object preserves those exact bindings. The caller's truthy error guard must abruptly return before every use that reaches the write. The schema argument must be the proved immutable schema. Cover every relevant return path, error assignment and mutation. A loop confined to the statically excluded GET query branch is irrelevant to that invocation; a loop affecting body or its proof is unknown. Unknown computed extraction still withholds unless the [closed GET query-copy certificate](get-query-copy-effects.md) also proves object/value provenance, all relevant source-world invocations and exact-node confinement. Method disjointness alone does not waive a source-world capability guard.

The write summary must prove that one parameter is forwarded unchanged into the literal data member of a resolved Prisma model create or update call. Resolve the client constructor through declarations and the verified generator output. Client provenance has its own bounded grammar: a named factory whose supported return branches all have the same verified generated-model lineage; immutable local aliases and object export members; and a fixed literal-key singleton cache whose known assignments preserve that lineage. Constructor adapter arguments do not establish validation or string clipping. Branches may choose separately constructed clients from the same generator. Unsupported proxies, dynamic keys, unknown factory returns or extra extensions withhold.

For the singleton form, resolve the constant cache key and inspect every in-repository TypeScript and JavaScript write to that key, including aliases, computed writes and deletes. Every writer must resolve to the admitted lineage; ambiguous dynamic writes and unread files stop the cache proof. This is a fact about the inspected source, not protection against arbitrary injected globals or a promise about external runtime state. Record that boundary in the binding witness. The cache form is permitted only if both cache population and uncached factory paths are proved; a conditional cold-cache-only finding cannot substitute for that proof.

The sole initial extension summary is @prisma/extension-read-replicas 0.5.0. The actual parent locks that artifact at pnpm-lock.yaml lines 32-34 and 1474-1475, with published integrity `sha512-t0kLjqFMte4wwGrZFhya4iFoyoOY4kjlyyE60WXZL66PqP6PcBpW/35eKb/3UcxgjJxcDlaJKfmGokFLOyafiQ==`. Its Prisma client is 7.6.0; do not substitute metadata from a later PR base. [Upstream commit 1177e51a014e1bc680ea3de0f811bb7d2427a769](https://github.com/prisma/extension-read-replicas/blob/1177e51a014e1bc680ea3de0f811bb7d2427a769/src/extension.ts#L65-L85) returns query(args) unchanged for create/update; replica selection covers its enumerated read operations. Implement the summary from the reviewed semantics without copying upstream source. Match the exact version and published integrity in a static reviewed table and the project's lock entry. The implementation must record the full integrity and source hash and review that table. Missing lock metadata, package patches, overrides that change the artifact, pnpmfile hooks, altered option shapes, wrapper substitution, extra extension chains or other versions withhold. Options are limited to an object with replicas consisting solely of clients already proved from that same generator. Never fetch or execute the extension. This is no new runtime dependency.

Track each field separately through property reads, object destructuring and literal object forwarding. The caller may forward a proved subset of fields; an unrelated transformed field does not erase another field's proof. A replacement, clipping operation, spread that can overwrite the field, reassignment, alias mutation, escaping object, computed property or unknown call receiving the value stops that field's proof. A helper with arbitrary side effects cannot be summarized as transparent by ignoring its other statements. A call that cannot access the primitive field, its schema or its containing object does not invalidate that field. Calls receiving those objects require a proved summary or withhold the affected proof. Reject loops, recursion and closures capturing mutable bindings on a relevant proof slice; a proven disjoint branch is excluded before this check.

Use fixed deterministic budgets: at most two value-forwarding helper boundaries (the parser and persistence wrappers), a separate maximum of four named functions for client initialization including generator/schema selection, 32 resolved source modules, 64 import/export resolutions per module, 10000 syntax nodes per proposed binding and the existing per-file byte/depth caps. Cache-write scanning additionally covers the complete source-file inventory within the extractor file budget; the 32-module resolution budget does not excuse an unread possible writer. Exceeding any budget is unknown with a stable diagnostic, not a shortened proof. Validate actual parser support and memory/runtime limits on the isolated verification host (a separate machine that holds the pinned sources and neither installs nor executes them) before adding coverage claims.

## Implemented source controls

The extractor shares immutable text, TypeScript AST and parsed metadata during one extraction. Its input LRU accounts for at most 8 MiB of source text and 2048 entries. Proposal module maps and memoized proof traces retain additional AST references; the sandbox applies a 512 MiB V8 heap cap and polls resident memory against a 768 MiB threshold, including its existing 256 MiB runtime headroom. Each proposed binding keeps its own 32-module, 64-resolutions-per-module and 10000-syntax-node budgets. Full-inventory safety walks are separate from that binding-slice syntax counter: they must visit every source AST within the 20000-entry and 8 MiB/file inventory caps, plus those existing sandbox memory controls and the 120-second child deadline. A reused source-world proof replays every binding-slice module, import-resolution and syntax charge that its operation recorded; exhausted budgets latch and cannot be cleared by a caught exception. Prisma metadata tokens consume that same syntax budget. No cache persists between extractions.

The complete source inventory includes unimported JavaScript and build directories. Symlinked metadata or source, unread directories and a capped walk cannot prove cache-writer completeness. Relative imports and supported single-target tsconfig aliases can be excluded from client resolution only when their metadata proves a disjoint basename; this supplies no provenance and still scans every source file. Nested package entrypoints, alternate resolver maps and relevant client re-exports remain refusals.

Strict class receivers are distinct from sloppy function `this`. The exact zero-argument BigInt `toJSON` scalar hooks returning `Number(this)` or `this.toString()` are supported; other prototype access or escaping builtin aliases withhold. Native `createRequire(import.meta.url)` is recognized only as a private immutable loader whose every use reads existing package JSON data by the supported direct or native path-resolution form. It supplies no executable module summary. The complete boundary remains inspected repository source, not external injected globals.

Client API aliases must remain confined. A query `$on` return is tracked as the same client. A `$transaction` input must be an inspected callback, a literal or immutable array, or a private source-proved dispatcher whose every exposed call is inspected. Callback client aliases cannot escape or mutate the client. These checks account for the [Prisma 7.6.0 client](https://github.com/prisma/prisma/blob/5fece0a97ca3f7a05a7ae6691d49728d19b795a4/packages/client/src/runtime/getPrismaClient.ts), rather than treating every transaction callback as unrelated data.

Plain Next configuration may use the reviewed next-intl 4.9.2 wrapper. Its artifact integrity is `sha512-AZoMRsVGLZczB2hisq1OTWmNAYAKwk/jaWH4+9pfl5TCG8kbILZZptZHux9zw7DyN1yzh6X7jmaQvoykHs9Y7Q==`; [source commit e1b18258075017216165735212568c8f795e1660](https://github.com/amannn/next-intl/tree/e1b18258075017216165735212568c8f795e1660/packages/next-intl/src/plugin) is recorded in `write-libraries.ts`, including configuration source SHA-256 `07c0547cd5a41ad1f3bb7b58de824d69a49bd49582bbb026f798cbdb510c9cc3`. The read-replicas source SHA-256 is `62454ecdee78cd0e500cb2aa9dc9f4d686fc074f6ae237aa68190987b21e6ecb`. Static semantic summaries add no dependency and copy no upstream source. Customized route resolution, hooks, patches or changed artifacts remain unknown.

The implementation recognizes candidate parser arguments by their relationship to the method request. An unrelated `permission(user, record)` call does not turn record into a schema. Unsupported but identifiable schema declarations retain names-only reservations for collision handling; these reservations emit no property or parse/forwarding credit. Opaque parser semantics, missing parser guards and extra parser options still withhold the complete binding, but cannot erase an otherwise identifiable collision reservation. Transparent argument wrappers and direct request aliases remain visible to both candidate discovery and names-only reservations even when full proof refuses them. A transformed argument referencing a local schema keeps the file uncertain. Complete caller proof requires an async handler for its awaited parse. Native module.require value escapes, process.mainModule and native process-module imports withhold client provenance. Source-world prototype and library-binding scrutiny applies to cached and uncached clients. Legacy getter/setter reflection also withholds. Reviewed library summaries require shared intrinsic roots to remain readonly and confined to direct calls or known scalar metadata; namespace or method escapes and intrinsic writes withhold. The existing exact primitive BigInt serializer and readonly Object.prototype forms retain their separate proofs. Dangerous or unknown computed property extraction through object destructuring withholds the proof, as does an escaping runtime Zod import. Computed calls may use a bounded finite set of literal keys, including readonly aliases and conditional choices, only when every possible key passes the capability checks. An unknown selector or any forbidden alternative withholds the proof. Unknown computed property extraction also withholds it because the value could carry a callable or prototype through an alias. This source-world restriction includes disjoint GET branches; a non-GET field-flow summary does not prove that another invocation cannot change a shared capability. Unknown calls using the parsed object as a method receiver invalidate its fields; argument packing through spread, call or apply keeps the route outside retirement authority. Request dependencies through local argument containers are followed for candidate reservation. A named write handler with no recognized candidate remains uncertain rather than proving absence. A request escape outside the admitted positional parser and readonly URL/method reads also withholds file authority, including a later container assignment beside a different complete binding. Implicit handler arguments also withhold authority because they can alias the request without a named-parameter reference. A destructured value must be a recognized positional parser result or a readonly alias of one of its outputs. Other origins withhold file authority even beside a complete binding; opaque, mutable or repackaged results cannot prove the old binding absent.

## Joining and detector behavior

The existing strict container rule remains. The proved Prisma storage identity supplies a domain fact for the property; do not infer it from a file path, operation name, schema suffix or arbitrary neighboring field. Resolve the data-side model and field through the existing extracted ORM mapping. Ambiguous model-to-table or field mappings withhold the candidate. Do not bypass the existing name/type/container checks or upgrade a heuristic edge into a fact.

X7 reads Column to SchemaProperty through the `COLUMN_TO_PROPERTY` join route (`packages/contradictions/src/joins.ts`: an `EXPOSED_AS` edge out of the column or a `BACKED_BY` edge into it; a route, not an edge kind). Both endpoints must pass isFact, be live, and carry the complete role/binding/length evidence above. Preserve join confidence multiplication and the central severity ceiling. Validator Symbol routes with synthetic constraint props cannot feed the rule.

Require data, contracts, code.ts and infer-join scopes. An unavailable required scope is UNKNOWN. With no supported observable pair, report a stable unknown reason rather than empty PASS. A supported pair whose input has a known bound can establish an examined negative control; an unproved binding cannot. Partial source coverage must preserve existing tombstone authority boundaries and must never retire an older fact merely because the new proof could not be completed.

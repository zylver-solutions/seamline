- **Predecessor designs:** the documents called v1 and v2 below are not published. Every reference of the form "v2 §N" is to that unpublished predecessor, not to a section of this document; what the review found in it is recorded in `docs/audit/2026-08-29-council-review-v2.md` and `docs/audit/2026-08-29-license-verification.md`.
- **Date:** 2026-08-29
- **Review record:** `docs/audit/2026-08-29-council-review-v2.md` (9-lens Tier-2 council, 11 CONFIRMED CRITICAL)
- **Name:** **Seamline**. The CLI command is `seamline`, installed from the npm package `@seamline/cli`. Every published package is in the `@seamline` scope and there is no unscoped `seamline` package ([aspirational-state.md](aspirational-state.md) §1.2 records why). Chosen 2026-08-29 over the working name _Atlas_, which was disqualified twice: `@ariga/atlas` declares `"bin": {"atlas": "atlas"}` at ~24k weekly downloads and owns the Homebrew `atlas` formula, so the CLI name is already on developers' PATH; and Apache Atlas (metadata + lineage) is a direct semantic competitor cited in this design's own prior-art table. ## 1. What this is now

**A zero-declaration cross-domain join, served to agents.**

v2's premise was a platform: 16 domains, ~235 node kinds, 193 edge types, 24 lenses, 15 extractors, 14 weeks to first release. Every high-value edge in it was `DECLARED` — hand-written by a human as a code annotation. The council's audit found that **only 5 of 24 lenses render anything without hand-authored edges**, and all five are already served by mature free tools. That design has no day-one value and therefore never earns the annotations it needs to have any.

v3 inverts this. The primary edge source is **inference over extracted facts**, not declaration. The primary output is **contradictions**, not gaps.

### The distinction that carries the design

|                                           | Gap (v2)                               | Contradiction (v3)                       |
| ----------------------------------------- | -------------------------------------- | ---------------------------------------- |
| Says                                      | "you failed to declare something"      | "two things you already wrote disagree"  |
| Input                                     | absence of a declared edge             | two extracted, authoritative facts       |
| Count on a fresh repo                     | 3,000–4,500 (council estimate)         | bounded by real disagreements            |
| Actionable                                | no — the fix is to write an annotation | yes — the fix is a code or schema change |
| Gameable                                  | yes — six documented escape hatches    | no — you must change a fact              |
| Asserts authoritative state, not presence | **no**                                 | yes                                      |

A gap is a complaint about documentation. A contradiction is a bug. v0.1 ships contradictions and defers gaps. (Declaration-driven gaps stay deferred. A separate, non-gating report of drift between a claim a document already makes and the implementation facts is admitted by [ADR-0014](../adr/ADR-0014-alignment-drift-classes-and-finding-packet.md) and is not this kind of gap.)

### The 10-minute acceptance test

This is a **gate, not an aspiration**. Nothing ships until it passes on a repo the author did not write, with zero declarations and zero annotations:

```
seamline init && seamline extract && seamline why
```

must produce, in under 10 minutes:

1. **A field-lineage map**: database column ↔ ORM/model field ↔ API schema property ↔ code type field ↔ validator, inferred by name, type, and structure matching, every edge tagged `INFERRED` with a heuristic confidence score.
2. **A ranked contradiction list** (§5), derived entirely from extracted facts.
3. **Blast radius for the working diff** — which columns, endpoints, and tests the current change reaches.

If a real repo yields an empty lineage map or an unranked wall of noise, the inference is wrong and the release does not happen.

### Why this is defensible

Attacked by three independent lenses as over-engineering; held every time, and named by the architect lens as "the wedge and the MVP's center". No surveyed project joins field-level identity across domains: Backstage stops at the component, FINOS CALM at the architecture node, SCIP at the symbol, DataHub has no domain or contract layer. Field-level cross-domain identity is the thing nothing else owns, and GDPR Art. 30 records fall out of it as a byproduct.

## 2. Non-negotiable invariants

These are the spine. Each fixes a CONFIRMED CRITICAL, each is unretrofittable after v1, and each carries a conformance test that is a CI gate rather than a guideline. Several are adopted **verbatim** from the decision record of an earlier internal project that independently reached the same design under its own council review, and which v2's prior-art survey missed entirely. That earlier project is not public, so nothing here depends on reading it: each adopted decision is restated in full in this section and recorded in [ADR-0002](../adr/ADR-0002-path-free-natural-key-identity.md), [ADR-0003](../adr/ADR-0003-run-lifecycle-tombstones-status.md), [ADR-0004](../adr/ADR-0004-sqlite-relational-storage.md) and [ADR-0007](../adr/ADR-0007-provenance-precedence-fact-label-separation.md).

### 2.1 Identity survives a rename _(fixes C3)_

- A node's id is a **path-free natural key**: `{repo}:{kind}:{canonicalName}`, for every kind except `File` (below). Not a synthetic UUID or ULID; the earlier internal project's own review rejected that explicitly, and it is right: an id minted at first sight is not stable across a rebuild-from-scratch, which is exactly the operation this design relies on ("the graph is derived, the registries are truth"). A natural key is reproducible, debuggable, and diffable.
- Natural key by kind: symbol = `(repo, canonical_qualified_name)` resolved through re-exports and barrels to the declaration site (ts-morph type-checker-backed); column = `(datasource, schema, table, column)`; schema property = `(contract, json_pointer)`; file = `(repo, repo_relative_posix_path)`, the one kind whose natural key is a path among the kinds an extractor emits today. (The ontology annotates `TestCase` as `(repo, test_file, test_name)`, which also contains a path; no extractor emits `TestCase`, and the amendments bullet at the top of `docs/design/real-world-inputs.md` records that annotation as conflicting with this rule and to be replaced by a path-free key.)
- **`path` is a property, never identity, for every kind except `File`** (the names that [ADR-0016](../adr/ADR-0016-file-identity-carries-its-path.md) item 4 lists as read from a file or directory name are inputs to an id, not the `path` property). It is stored on the node, and additionally as `src_file`/`dst_file` on every edge, because the re-run invalidation rule needs it (any edge whose source or destination file changed is re-resolved).
- A rename pass consumes `git diff -M` rename detection plus content hashes. A `File` id is its path, so for a file that git reports as renamed the pass records an `Alias` node (`{repo}:Alias:File::<old path>`) and an `ALIAS_OF` edge from that node to the new `File` id, and history is preserved across the rename. That holds for a committed rename that git reports at or above the similarity threshold (0.6 by default), within the history window (500 commits by default), with `extract-change` enabled. A staged but uncommitted `git mv` is not reported; below the threshold the move is a delete plus an add and no alias is written. Only file renames are aliased today; symbol-level rename detection is deferred (§9).
- **Where the guarantee stops.** A `git mv` changes no id except the moved `File`'s own, unless it changes an input that the id is built from. [ADR-0016](../adr/ADR-0016-file-identity-carries-its-path.md) item 4 states the rule and lists the inputs, and says how the list was derived; item 3 carries the consumer rule that follows from keeping the `File` id path-bearing. None of these changes is aliased.
- **Conformance gate:** `git mv` a file, re-extract, assert that no id changes except the moved `File`'s (for a move that changes an input ADR-0016 item 4 lists, exactly the ids built from that input), that the edge keys that change are those that have a changed id as an endpoint, plus the path-dependent edges that [ADR-0016](../adr/ADR-0016-file-identity-carries-its-path.md) item 4 ("Edges") discloses: a `Module` `EXPORTS` edge when the package entry file is renamed, and automatic inferred joins whose path eligibility or path-based corroboration changes membership, and that the retired `File` id resolves through the alias table to the new one. The assertions are split across tests, and each states only what it builds:
  - `packages/core/src/identity/identity.property.test.ts` asserts over randomized repositories and moves that `Symbol` ids and `CALLS` edge keys are unchanged, that a rename at or above the threshold yields an alias and one below it does not, and that the library function `rewriteEdges` over the pre-move edges equals the edges of a re-extraction. `rewriteEdges` has no production caller, so nothing in the pipeline rewrites stored edges: `File`-keyed facts are re-derived on each run (a `CONTAINS` edge follows the file's current path; a `TOUCHES` edge keeps the path the commit touched and is joined to the current path by `RENAMED_FROM` and the alias), and the test uses the library rewrite as a proxy for re-extraction.
  - `packages/extract-code-ts/src/extract.test.ts` asserts the `Symbol`, `CodeField` and `Parameter` ids and the edges between non-`File` nodes after a fixture file is renamed; `packages/extract-data/src/extractor.test.ts` asserts every node id and edge for the same schema at a different path; `packages/extract-contracts/src/zod-coverage.test.ts` does the same for a Zod contract. None of these changes an input that ADR-0016 item 4 lists.
  - `packages/cli/src/wiring.test.ts` asserts the `Alias` node and the `ALIAS_OF` edge from each retired path to the current `File` after a file is renamed twice with a real, committed `git mv`.
  - `packages/integration/src/rename-id-boundary.test.ts` runs `extract-code-ts`, `extract-data` and `extract-contracts` over one fixture repository and asserts, for an illustration of each input in ADR-0016 item 4, the exact non-`File` ids and edge keys that change, and that moves and renames that change none of those inputs change no id.
  - `packages/integration/src/join-eligibility.test.ts` runs real extraction across an ordinary eligible move and a fixture-boundary move, asserting stable semantic ids, stable join keys for the ordinary fixture move, removed joins in the fixture path, and restoration on return. Other eligible moves can change path corroboration and therefore scores or membership; this is not an identity change.

### 2.2 The graph can forget _(fixes C2, C7)_

Adopted from the earlier internal project's tombstoning decision, extended with its own PASS/FAIL/UNAVAILABLE envelope semantics.

- Every extraction is a **run** with `run_id`, `started_at`, and a declared **authoritative scope**: the `(kind, selector)` pairs this run is the authority for.
- Every node and edge carries `first_seen_run`, `last_seen_run`, `deleted_at`, and `run_id NOT NULL`.
- After a run, core diffs the run's authoritative scope against the prior run for that same scope and **tombstones** what vanished. Never hard-delete.
- **`deleted_at` must be cleared on re-insert.** A tombstoned node that reappears is resurrected, not shadowed. An earlier internal project shipped this as a bug; it is called out here so this implementation does not repeat it.
- Edge uniqueness: `UNIQUE(scope, src_id, dst_id, kind)`.
- Every extractor reports `status ∈ {PASS, FAIL, UNAVAILABLE}` plus counts. **UNAVAILABLE is never PASS.** Any query whose answer depends on a scope whose producing extractor did not PASS returns `UNKNOWN` for that portion and **never** a negative finding.
- **Conformance gates:** delete a source file, re-extract, assert the symbol is tombstoned and its edges stop being returned. Kill an extractor mid-run, assert zero contradictions are reported from its scope and that the affected queries return UNKNOWN.

The second gate is the one that matters. Without it, infrastructure flakiness manufactures false findings, which is the fastest way to make a CI gate get switched off.

### 2.3 Extraction is byte-reproducible _(fixes C11, H3)_

Golden-file testing is worthless without this, and so are `seamline diff` and any merge driver.

- Canonical SIF serialization: object keys sorted, arrays sorted by stable id, repo-relative POSIX paths only, **no absolute paths**, fixed float formatting, `\n` endings.
- [ADR-0018](../adr/ADR-0018-canonical-name-authority.md) coordinates version-2 framing before canonical claims: complete documents begin with `seamline-sif/2.0.0` and LF, then the existing JSON record union. [Compatibility and migration](../canonical-authority.md) describe old-reader refusal and legacy input handling.
- **No wall-clock timestamp appears in a node or edge body.** Timestamps belong to the run, not to the fact. (v2 put `created_at`/`updated_at` on every node, which alone makes byte-identical output impossible.)
- [ADR-0009](../adr/ADR-0009-determinism-release-gate.md) distinguishes the existing typed HTTP route values from filesystem locators, and immutable Git author/committer dates from observation time. Those bounded source-data exceptions require matching identities and canonical values; runtime timestamps and absolute filesystem locators remain forbidden.
- `SEAMLINE_DETERMINISTIC=1` freezes the clock and normalizes emission order. It does **not** freeze the run id: that is derived from the run's inputs (the tree's content, the effective config, and the extractors with their versions), so identical inputs give identical bytes and different inputs give different ids. The id is an identity and not an ordering, and the same inputs run twice into one store are one run repeated, idempotently (ADR-0009 §3a).
- **Conformance gate:** extract twice, assert byte-identical SIF.

### 2.4 Provenance is enforced, not declared _(fixes C6; preserves v2's strongest idea)_

v2's four-tier provenance model was attacked as bookkeeping bloat by three lenses and held every time. It is the mechanism that lets agents write to the graph without corrupting it, and nothing in the current AI-codebase-graph crop has it. v2 buried it as principle 1; here it is load-bearing.

- `provenance ∈ {EXTRACTED, INFERRED, DECLARED, LLM_SUGGESTED}` with a **total precedence order** for merge: `EXTRACTED > DECLARED > INFERRED > LLM_SUGGESTED`, tie-broken by `(extractor_priority, run_id)` so merge is deterministic regardless of input order.
- An extractor **may not assert a provenance level above the ceiling in its manifest**. A plugin cannot label a guess as `EXTRACTED`.
- `INFERRED` and `LLM_SUGGESTED` live in a **separate insert-only table** and never mutate the facts tables (the separation is structural, not a convention). On the Postgres adapter this is **enforced at the GRANT level**, not by application code: the writer role for inference has INSERT on the annotations table and no UPDATE or DELETE anywhere. A `provenance` enum column alone is a weaker control, because a bug in one code path defeats it. Keep the enum _and_ segregate the storage.
- **Note (2026-11-10): as implemented in 0.1.0, the storage is not segregated.** The SQLite store, the only persistent store that exists, has one `nodes` table and one `edges` table, each with a `provenance` column constrained to the four values above, and `INFERRED` rows such as the joins `infer-join` emits are stored in `edges` beside extracted facts (`packages/core/src/store/schema.ts`). There is no annotations table and no Postgres adapter, so the GRANT-level control in the previous bullet is the design for that adapter and is not implemented. What the code enforces is the read side: a detector accepts only `EXTRACTED` or `DECLARED` nodes as facts (`isFact` in `packages/ontology/src/contract.ts`), may follow an `INFERRED` join edge between two fact nodes, and drops every `LLM_SUGGESTED` edge (`packages/contradictions/src/graph.ts`).
- Promotion to `DECLARED` writes a new row that retains PROV-O `wasAttributedTo`; v2 lost attribution on promotion.
- Contradiction detection reads **facts only**. Inference never feeds a gate.

### 2.5 Export is default-deny _(fixes C5, C8)_

What Seamline builds is, in one queryable file, the complete attack map of an organization: every entry point, every endpoint's auth mode _including the null ones_, every secret reference and the function that reads it, every dependency CVE, every IAM role, certificate expiries, the under-tested high-risk surfaces, and the ownership map. v2 instructed the user to commit it to git.

- `sensitivity ∈ {public, internal, confidential, restricted}` on every node, defaulted **per kind** (infrastructure, security findings, and people default to `restricted`).
- `seamline export --profile <name>` where a profile is an **allow-list**. No profile, no output. There is no "export everything".
- `seamline init` writes `seamline-out/` into `.gitignore`. Snapshots are never committed by default.
- A **`Redactor`** runs post-merge as the **sole writer** to the store: entropy and pattern scan over every free-text string field; a matched secret is replaced by a reference, never a value. Identity and path fields are never rewritten: they are scanned for closed-format credentials only, and a match refuses the record (ADR-0013). v2's entire security assertion was the parenthetical "(values never stored)" with no component behind it.
- Terraform: **HCL source and `terraform graph` only.** Never state, and never plan — v2's §12 claimed plan files are safe, which is false.
- `THREATMODEL.md` is a Phase-0 deliverable. The ontology has a `ThreatModel` kind; Seamline is its own first user.

### 2.6 The query surface is bounded and typed _(fixes C5)_

- **`cypher` is removed from the store interface.** It was unimplementable on two of its four v2 adapters, and on the Postgres/AGE adapter it was arbitrary query execution inside the database.
- The internal interface is a **typed traversal API** with depth bounded by construction, plus `statement_timeout` and a result cap.
- MCP in v0.1 is **stdio-only, parameterized tools only, no raw query tool**, with per-tool scopes and an audit log.
- Every string field sourced from third-party content (dependency metadata, issue and PR text, commit messages, code comments) is tagged `untrusted` and delimited when rendered into agent context. An attacker who lands a comment in a dependency must not be able to instruct a Builder agent.
- **No externally-reachable query surface without a named consumer.**

### 2.7 Extractors are sandboxed _(fixes C5)_

The plugin contract is third-party code execution by design. v2 specified no sandbox while planning for community extractors.

- Every extractor ships a capability manifest: `{ reads: [globs], net: false, env: [allow-list], mem_mb, timeout_s, provenance_ceiling }`.
- The host **enforces** it: scrubbed environment (no `AWS_*`, no `KUBECONFIG`, no SOPS keys), reads confined to the repo and the extractor's own code with no filesystem writes (an allow-list and a guard, not a read-only mount), no network by default, wallclock and memory caps.
- Third-party extractors live in `contrib/`, are unsigned by default, and are refused unless explicitly enabled.
- XML external entities disabled globally; `$ref` resolves only within the repo root with no network fetch; parse depth and input size capped.

## 3. Storage

**v0.1 ships one store.** v2 named four behind one interface; the council found the interface unimplementable on two of them, and the stated default carries a continuity risk v2 did not disclose.

On LadybugDB specifically, two lenses returned partially conflicting evidence and the reconciled position is: the project **is** real and MIT (`LadybugDB/ladybug`, ~1,685 stars, active release cadence through v0.20.0 on 2026-08-29), but it is an 11-month-old fork of **Kuzu, which was archived 2025-10-10** when its team was acqui-hired, its **bus factor is 1** (19 of 21 commits since 2026-06 from a single contributor, all releases published by that contributor), it is pre-1.0, and **three competing MIT forks of Kuzu are contesting the succession**. v2's claim that it offers "Bolt server mode" is **false** — the documentation describes embedded-only operation, and upstream Kuzu never had Bolt either, which orphans v2's `bolt` adapter entirely.

- **Default: SQLite via `node:sqlite`, built into Node — zero dependencies.** Relational schema generated from the ontology; bounded traversal by recursive CTE. Embedded, no listener, no default network surface, boring.
- **`graphology` (MIT) in-memory** for the algorithm workloads (PageRank, community detection) — exactly as v2 already planned, since those already routed around the primary store. Note (2026-11-10): not implemented in 0.1.0. `graphology` is not a dependency of any package and the code has no PageRank or community-detection workload.
- **Postgres adapter** is a planned deployment target: same generated schema, same traversal API, a tenant-id `NOT NULL` column + `FORCE ROW LEVEL SECURITY` from the first migration, **no new Postgres extension**. Support requires the same traversal conformance suite as the default store.
- **Dropped from v0.1:** LadybugDB (single-maintainer pre-1.0 fork of an archived database, contested succession), Apache AGE, Kuzu, Bolt (the mode does not exist). Each may return as an adapter when a named consumer requires it.
- **Parity rule:** two stores are "supported" only when both pass the identical traversal conformance suite. Adapter-compatible is not dialect-compatible.

**Why not a graph database at all.** Every one of v2's 24 lenses is bounded-hop, and the single unbounded-traversal workload already exports to graphology by v2's own plan. No lens in the design justifies a graph store, and choosing one imported a dialect-compatibility project as a side effect. The licensing lens recommended Apache AGE over LadybugDB as the safer _graph_ default, which is correct **given the premise that a graph store is needed** — v3 rejects that premise instead, which also removes the `CREATE EXTENSION` that the no-new-Postgres-extension rule above forbids. This is the cheaper answer to the same problem: no exotic dependency, no dialect divergence, no extension.

## 4. Core profile ontology

v2's council demanded a "~35-kind core profile or adoption dies on day one" and then shipped all 16 domains anyway. Here the profile is a **field on every kind**, enforced by lint, not a paragraph.

- Authored in LinkML (`ontology/seamline.yaml`), which survived refutation as genuine leverage for a one-person team: one source generates JSON Schema, TypeScript types, the SQL DDL, and docs.
- **Note (2026-11-10): as implemented in 0.1.0, only the reference documentation is generated from the LinkML source.** `scripts/gen-ontology-ref.mjs` writes `docs/reference/ontology.md` from `ontology/seamline.yaml`. The TypeScript contract (`packages/ontology/src/contract.ts`) is written by hand, `ontology/lint.mjs` fails when its kinds, edge signatures or default sensitivities differ from the YAML, and the SQL DDL in `packages/core/src/store/schema.ts` is built from the arrays in `contract.ts`. No JSON Schema is generated from the ontology. The same applies to "schema generated from the ontology" in §3 and to the first Ontology row in §7.
- Every kind carries `profile: core | extended | vendor`. **v0.1 extractors emit `core` only.** As of 0.1.0 every kind in the source is `core`: `extended` and `vendor` are reserved values of the profile field, and no kind carries either.
- **Every edge declares domain and range.** v2's containment edges (`CONTAINS`, `PART_OF`, `CHILD_OF`, …) were declared "all domains" with no constraint, which is how the design ended up with no `Component → File` edge at all (C10) while four lenses traversed it.

### Core kinds (29)

| Group        | Kinds                                                                                                                                        |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Code         | `Repo`, `File`, `Module`, `Symbol` (Class \| Interface \| TypeAlias \| Enum \| Function \| Method), `CodeField`, `Parameter`, `RouteHandler` |
| Data         | `DataSource`, `Schema`, `Table`, `Column`, `Migration`                                                                                       |
| Contract     | `Contract`, `Operation`, `SchemaProperty`                                                                                                    |
| Domain       | `Entity`, `DomainProperty` _(declared-only, optional — the graph works without them)_                                                        |
| Verification | `TestCase`, `TestRun`, `CoverageRecord`                                                                                                      |
| Change       | `Commit`, `Changeset`                                                                                                                        |
| People       | `Owner` _(from CODEOWNERS)_                                                                                                                  |
| Meta         | `Run`, `Extractor`, `Contradiction`, `Alias`, `Lens`, `ThreatModel`                                                                          |

### Core edges — 26 kinds over 54 declared domain/range pairs

Every edge declares its endpoints. The list below groups by purpose; `CONTAINS` is a single edge kind carrying 12 enumerated pairs, which is why an edge-kind count and a pair count differ.

- **Containment (enumerated pairs, never "all domains"):** `Repo→File`, `Repo→Module`, `Module→File`, `File→Symbol`, `Symbol→CodeField`, `Symbol→Parameter`, `DataSource→Schema`, `Schema→Table`, `Table→Column`, `Contract→Operation`, `Contract→SchemaProperty`, `Entity→DomainProperty`
- **Code:** `IMPORTS`, `EXPORTS`, `CALLS`, `EXTENDS`, `IMPLEMENTS`, `USES_TYPE`, `DECORATED_WITH`, `HANDLES_ROUTE`, `QUERIES` (Symbol→Table)
- **Data:** `MIGRATED_BY`, `FK_TO`
- **Contract:** `IMPLEMENTED_BY` (Operation→RouteHandler)
- **The join — the wedge, mostly `INFERRED`:** `MAPS_TO_FIELD` (Column→CodeField), `BACKED_BY` (SchemaProperty→Column), `EXPOSED_AS` (Column\|CodeField→SchemaProperty), `VALIDATED_BY` (CodeField\|SchemaProperty\|Column→Symbol), `PERSISTED_IN` (Entity→Table), `STORED_IN` (DomainProperty→Column)
- **Verification:** `TESTS` (extracted), `COVERS`
- **Change:** `TOUCHES`, `RENAMED_FROM`
- **Meta:** `PRODUCED_BY` (node→Run), `ALIAS_OF`, `OWNED_BY`

**Reification.** v2 required three edges that put edges and types in node positions (`CROSSES`, `PROPOSED`, `PROJECTS`), which no property-graph store supports. Here `Contradiction` is a **node** referencing two facts, not an edge between edges.

## 5. The contradiction catalog

This is what makes the wedge real, and it is the deliverable that must be right. Each detector names the **authoritative facts it compares** — never the absence of a declaration.

| #   | Contradiction                 | Compares                                                                                            | Severity     |
| --- | ----------------------------- | --------------------------------------------------------------------------------------------------- | ------------ |
| X1  | Nullability disagreement      | `Column.nullable` vs response `SchemaProperty.nullable` / role-proven `CodeField.nullable`          | high         |
| X2  | Type disagreement             | `Column.type` vs `CodeField.type` vs `SchemaProperty.type` across a join                            | high         |
| X3  | Width/constraint disagreement | `Column` length or check constraint vs the validator enforcing it                                   | medium       |
| X4  | Unbacked response property    | `SchemaProperty` on a response with no `BACKED_BY` column and no computing symbol                   | medium       |
| X5  | Unwritten required column     | `Column` NOT NULL with no default its writers supply, omitted by every complete traced insert       | medium       |
| X6  | PII reachable without auth    | `Column.pii ≠ none` reachable from an `Operation` with no declared auth                             | **critical** |
| X7  | Validator/database divergence | a source-proved unbounded validated request string reaches finite-length storage                    | high         |
| X8  | Orphaned migration            | `Migration` referencing a `Table`/`Column` that no longer exists                                    | low          |
| X9  | Contract drift                | `Operation` with no `IMPLEMENTED_BY` route handler, or a handler implementing no declared operation | high         |
| X10 | Untested write path           | a symbol that writes a `Column` with `pii ≠ none` and no `TESTS`/`COVERS` intersecting it           | medium       |

X1 and X2 withhold generic code-field comparisons until a shipped fact establishes a stored-row or insert role. X1 also withholds request-omission comparisons and unknown-direction schemas. These precision boundaries, including the retired demo claim, are specified in [precision-boundaries.md](precision-boundaries.md).

Implemented is not the same as externally qualified. X3 and X10 lack producer facts and remain synthetic-only. X8 has authored declared-DDL extraction proof, with complete named parent/fix acceptance and independent qualification still pending. X7 has the narrow [upper-length producer](x7-upper-length.md) and a [historical parent/fix reproduction](../evaluation/x7-parent-fix.md). [Later hardened candidates](../evaluation/x7-hardening-refusals.md) return UNKNOWN on that target; current acceptance, independent labelling and sealed precision remain unmet. X5 has authored extraction fixtures only and remains dormant on its measured unmodified corpus (§9). X4 and X9 cover only part of their row.

**False-positive controls are part of each detector, not an afterthought.** Every detector states its required extractor scopes; if any of those scopes is not `PASS`, the detector emits `UNKNOWN` rather than a finding (§2.2). Every detector carries a fixture pair (one firing, one not) and a meta-test asserting it can both fire and not fire — a detector that always fires and one that never fires are equally useless and equally invisible.

## 6. Extractors in v0.1

Three source extractors, one git change extractor and one inference pass, not fifteen. v2's 12+ extractors across Terraform, Helm, Temporal, Prisma, Playwright, OTel, and SBOM created a maintenance surface only one person could service, in stacks he does not run — estimated at 1–2 person-weeks per month, forever.

| Extractor           | Input                                                                                                                             | Provenance ceiling |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| `extract-code-ts`   | TypeScript/JavaScript via **ts-morph** type-checker-backed resolution through re-exports and barrels to the canonical declaration | EXTRACTED          |
| `extract-data`      | SQL DDL, Drizzle and Prisma schema files, migration files. **Static files only — no live database introspection in v0.1.**        | EXTRACTED          |
| `extract-contracts` | OpenAPI, JSON Schema, Zod schemas                                                                                                 | EXTRACTED          |
| `extract-change`    | git via a `git` subprocess (no git library): commits, `TOUCHES`, `git log --find-renames` rename detection feeding §2.1           | EXTRACTED          |
| `infer-join`        | the wedge — name, type, and structure matching across the above                                                                   | INFERRED (ceiling) |

`infer-join` **cannot** emit `EXTRACTED`; the manifest ceiling makes that a runtime error, not a code-review question.

## 7. Test architecture

v2 mentioned testing once in 485 lines and had zero test deliverables across seven phases, for a project whose entire pitch is verification. Each layer below names the component, the technique, and the invariant asserted.

| Component                | Technique                                                                                  | Invariant                                                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| Ontology                 | LinkML compile + generated-artifact round-trip                                             | the generator pipeline is lossless; LinkML is the only hand-edited source                                                             |
| Ontology                 | reachability lint                                                                          | every kind is the source or target of >= 1 edge, or is explicitly waived                                                              |
| Ontology                 | domain/range lint                                                                          | no edge is used outside its declared domain and range — including by rules and lenses                                                 |
| Ontology                 | evolution test                                                                             | schema N vs N-1 flags breaking changes; breaking requires a major bump                                                                |
| Extractors               | golden-file snapshot over **canonical** SIF                                                | structural match, plus byte-identical output across two consecutive runs                                                              |
| Core merge + ID resolver | **property-based** (`fast-check`)                                                          | merge is associative, commutative, and idempotent across randomized orderings; identity is stable under whitespace-only re-extraction |
| Provenance               | unit tests over the total precedence order                                                 | a deterministic winner regardless of merge order                                                                                      |
| Lifecycle                | integration                                                                                | tombstoning on vanish; UNAVAILABLE never yields a finding                                                                             |
| Contradiction detectors  | fixture pair per detector + meta-test                                                      | every detector both fires and does not fire; none is vacuous                                                                          |
| Traversal API            | conformance suite run against **every** adapter                                            | identical results across SQLite and Postgres (as of 2026-11-10 SQLite is the only adapter; no Postgres adapter exists, see §3)        |
| Redactor                 | canary-secret corpus                                                                       | a planted secret never reaches the store or any export                                                                                |
| Dogfood                  | `seamline extract && seamline why` on Seamline itself, diffed against a committed baseline | no unreviewed regression                                                                                                              |

The dogfood gate is the credibility test: an OSS project selling verification that does not pass its own gate is not shippable.

## 8. CI and release

Public pull requests receive visible verification checks. Package publishing is defined in `.github/workflows/release.yml`; its release gates and publishing requirements must be satisfied before every publication. Version 0.1.0 was published to npm on 2026-11-10.

Actions are pinned to reviewed commit SHAs. The release job requests an OIDC token and passes `--provenance`. A passing dry-run does not prove a published attestation; release verification must inspect the resulting package provenance.

- **Public CI (`.github/workflows/`):** lint, typecheck, unit, property, conformance, determinism gate, license allow-list gate, SBOM, dogfood gate, npm publish with provenance.
- **Adapter parity:** optional deployment adapters must run the same verification pipeline and traversal conformance suite before being described as supported.
- `packages/ci` ships the GitHub Action as a **product artifact for adopters**, split `ci-core` / `ci-github` / `ci-argo` so the adapter is not GitHub-first. Note (2026-11-10): this is not implemented. There is no `packages/ci` directory and no such package is part of 0.1.0; it is deferred (§9).

## 9. Deferred, each behind a named consumer

Adopted from the earlier internal project's own gating rule: a stage does not start until a **named consumer** exists and it has had its own design-spec pass. This is what prevents v3 from re-growing into v2. The gate has since been refined into a three-leg admission test (a cited instance, a named owner, and the design-spec pass), defined in [aspirational-state.md](aspirational-state.md) §5.3; read "named consumer" in this section as that test.

Deferred: the web viewer; all 24 lenses (the CLI emits lineage and contradictions as human-readable text, or as JSON with `--json`; CSV and Mermaid output are not implemented); the needs matrix as a CI gate; 12 extractors (env, workflow, ops, supply, verification, SCIP, Joern/CPG, graphify, OpenLineage, Cartography); CALM / Backstage / Structurizr / GraphML export; domains D1 (product/OKR), D11 (ops), D15 (agent); live database and cluster introspection; the Bolt, AGE, and Kuzu adapters; broader ORM column mapping (Prisma, Drizzle, and similar) and arbitrary field-level query read/write lineage; the adopter-facing GitHub Action of §8 (`packages/ci`, added to this list on 2026-11-10 because it is not implemented). The bounded raw-SQL write facts described below are implemented, with admission and evaluation requirements still unmet.

**Admitted since:** one non-gating report that compares what the documents already claim with the implementation facts, `seamline align`, decided in [ADR-0014](../adr/ADR-0014-alignment-drift-classes-and-finding-packet.md) and specified in [`alignment.md`](alignment.md). It is a second report family beside the contradiction pipeline and adds no node kind, edge kind or extractor.

**On column-level write extraction specifically.** `extract-code-ts` emits bounded raw-SQL write measurements on `QUERIES` edges, including `insertColumns` and `insertComplete`. X5 can fire on authored repositories passed through actual extraction, while writer, runtime-DDL and data-replay guards make it UNKNOWN or withhold tables where measured facts are incomplete. Its `insertOrm` branch is fixture-only; no shipped extractor emits that property. Current firing on an unmodified non-self corpus repository is unverified, and no verified real-world true positive, successful admission or validated precision is established. The three historical parent/fix findings were false positives. X5 remains disclosed dormant pending evaluation; the cited-instance and acceptance requirements remain unmet ([real-world-inputs](real-world-inputs.md) sections 2, 6.5 and 8.1). The runtime-DDL safety fix and historical-finding triage do not waive those requirements or admit broader ORM mapping or arbitrary field-level lineage.

**On detectors whose input facts no shipped extractor emits.** X3 reads validator Symbol constraints that no shipped extractor emits. X10 needs TestCase/TESTS and CoverageRecord/COVERS facts from the deferred verification extractor. Their synthetic fixtures supply those absent facts and do not establish real coverage.

**On the admitted X7 upper-length relationship.** [The reviewed design](x7-upper-length.md) admits only a complete validated request-body binding into one scalar Prisma model field. The producer emits length and binding facts on SchemaProperty; X7 follows the column-to-property join route (`COLUMN_TO_PROPERTY` in `packages/contradictions/src/joins.ts`, a route constant and not an edge kind: an `EXPOSED_AS` edge out of the column or a `BACKED_BY` edge into it) and requires current successful extraction authority. Its [historical parent/fix proof](../evaluation/x7-parent-fix.md) reported five findings clearing under the fix, but [later hardening](../evaluation/x7-hardening-refusals.md) withholds that case as UNKNOWN. Required real-source implementation acceptance is unmet. This grants no general ORM QUERIES producer, X3 inequality comparison, other X7 dimension or independent precision qualification.

**On historical migration references.** The [X8 replay design](x8-migration-replay.md) admits a bounded declared-DDL producer for the named parent/fix consumer. The implementation emits versioned Migration/DataSource replay certificates and compares references with group-local historical table and column state. Legacy target-property and tombstoned-edge routes are removed. Authored extraction and SQLite controls do not satisfy the required complete consumer CLI acceptance, independent evaluation, calibration or formal recall. X8 remains dormant for evaluation until the named non-self-authored acceptance is proved ([detector limits](../contradictions/X8.md)).

**On symbol-level rename detection specifically.** Only file renames become aliases today: `seamline extract` folds `extract-change`'s `git diff -M` rename records into `File` `Alias` nodes and `ALIAS_OF` edges (§2.1). Detecting that a symbol, field, or column was renamed needs matching across commits that git does not provide, so it is deferred until a named consumer needs it and it has had its own design-spec pass.

**On a single export-profile format.** Done, in `docs/design/export-profile.md`. There is one profile format (`version: 1`), parsed by `parseExportProfile` in `@seamline/core`: shipped profiles (`public`, `team`, `audit`) and profiles declared under `exportProfiles` in `seamline.config.json` are the same type, and `seamline export` and `seamline mcp` resolve a name and apply it through the same code. The consumers that lifted the deferral are named there: `export`, the MCP server, and the alignment packet's profile opt-in (ADR-0014). The semantic layer's disclosure stays its own optional layer and does not use this format. The file is `docs/reference/export-profile.schema.json`.

**On languages other than TypeScript and JavaScript.** Only `extract-code-ts` produces code facts, so code in any other language is not extracted, and the absence of a fact about it is not evidence of anything. A language front-end inside this repository would be extractor sprawl, and a regex-grade extractor is refused outright. The shape that would fit is an out-of-tree extractor port: a separate package emitting SIF that the host validates against a capability manifest, a provenance ceiling and the edge signatures, and that reports scope status like any other extractor. It needs a named consumer and its own design-spec pass before work starts.

**On the needs matrix specifically.** It survives as a design, not as v0.1 behavior. When it lands, any rule at `severity: error` must cite **authoritative evidence** — a `TestRun` result at the commit plus coverage intersecting the realizing symbols — never a substring in a test name. v2's `VERIFIES` rule was satisfiable by `it('[F-042] works', () => expect(true).toBe(true))` clearing an error-severity CI gate. Suppressions become expiring `Waiver` nodes with an owner and a reason, counted in the readiness denominator, and a `risk_class` downgrade emits its own finding.

## 10. License policy

Carried from v2 §9, which survived refutation by three lenses as a genuine distribution asset rather than compliance hygiene — permissive-only is what makes this embeddable inside a Backstage plugin, an IDE extension, or another vendor's agent framework, which is the only distribution path available here.

- **Allowed (runtime and build):** MIT, Apache-2.0, BSD-2/3, ISC, CC0, Unlicense, 0BSD, Zlib, PostgreSQL, MPL-2.0 (unmodified dependency only, with notice), **BlueOak-1.0.0**, **Python-2.0**.
  - `BlueOak-1.0.0` added 2026-08-29 after verification against primary sources. OSI-approved 2024-01-19; permissive and non-copyleft (no source-disclosure, reciprocal, or network-use clause); express patent grant with no termination clause, so no Apache-2.0 conflict; the Blue Oak Council rates it _Model_ tier, above the _Silver_ tier that holds Apache-2.0, MIT, ISC, BSD-2 and PostgreSQL. **Notice obligation is live**: it reaches us through `minimatch`, which sits on the runtime path via `@ts-morph/common`, so any bundled artifact must carry the package name and `https://blueoakcouncil.org/license/1.0.0` in `THIRD-PARTY-NOTICES.txt`. Its notice scope is "any part", broader than MIT's "substantial portions" — there is no de-minimis snippet exemption.
  - `Python-2.0` added the same day: OSI-approved, permissive, GPL-compatible, no copyleft. Dev-tree only, via `argparse` ← `js-yaml` ← `@eslint/eslintrc`.
  - Both were surfaced by the gate **failing closed** on an unrecognised identifier rather than passing it through, which is the behaviour §10.1 exists to produce.
- **Excluded:** GPL/AGPL/LGPL-linked, SSPL, BSL/source-available, PolyForm, CodeQL CLI terms.
- **Enforced from commit one** by a license allow-list gate plus a CycloneDX SBOM of Seamline itself — not retrofitted. v1 of this design recommended FalkorDB, which would have made the package undistributable; catching that class of error before code exists is the entire point.
- Project license (Apache-2.0 for code, CC-BY-4.0 for the ontology and specification text) and contribution model (DCO, no CLA): decided in [ADR-0010](../adr/ADR-0010-licensing-apache-cc-by-dco.md).

### 10.1 The defect an allow-list cannot catch

**v2 §1 never distinguishes implementing a published format from copying source, and Apache-2.0 code cannot be relicensed as MIT.** The prior-art table uses "adopt", "borrow", and "reuse" interchangeably across nine Apache-2.0 projects. Adopting CALM's _schema_ or Backstage's _vocabulary_ is spec-compatible reimplementation and is fine. Vendoring Graphify's merge driver or Cartography's intel modules is code derivation and carries the upstream license with it. No `license-checker` allow-list detects this, because the offending code arrives as a copy-paste rather than a dependency. This is the FalkorDB class of error in a subtler form.

**Applied:** every prior-art row is re-tagged `SPEC-COMPATIBLE` or `CODE-DERIVED`, defaulting to spec-compatible, and a `CODE-DERIVED` row requires a recorded license-compatibility decision plus NOTICE propagation before any code lands.

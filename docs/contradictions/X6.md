| Required scopes   | `contracts`, `code.ts`, `data`, `infer-join`                                                |

Citations are relative to `packages/contradictions/src/` unless the path starts with `packages/`. Shared mechanics are on the [index](README.md).

## What it compares

Two facts joined by a traced call path:

- An `Operation` that **declares** it requires no authentication (`Operation.auth` or `Operation.authMode`, `props.ts:161-166`).
- A `Column` that is classified as PII (`Column.pii` other than `none`, weighted by `piiProvenance` and `piiConfidence`, `props.ts:90-114`).

The path is `Operation -IMPLEMENTED_BY-> RouteHandler <-HANDLES_ROUTE- Symbol`, then zero, one or two `CALLS` hops, then `Symbol -QUERIES-> Table -CONTAINS-> Column` (`joins.ts:41-45`, `detectors/x6-pii-unauthenticated.ts:81-85`).

## When it fires

When an extracted `Operation` has an auth mode in `{none, public, anonymous}` (case-insensitive, `detectors/x6-pii-unauthenticated.ts:61`, `:78-79`), the handler or a function within two calls queries a `Table`, and that table has a `Column` with `isPiiColumn` true. If the `QUERIES` edge names columns, only a named PII column counts; if it names none, every PII column of the table counts (`detectors/x6-pii-unauthenticated.ts:94-98`). Tests: `detectors/x6.test.ts:55-63` (fires for `none`, `public`, `anonymous`), `:87-95` (follows `CALLS`, names the whole path).

## When it must not fire

The distinction this detector exists to make (`detectors/x6-pii-unauthenticated.ts:1-41`):

| Declared auth                 | Reading                                   | Behavior                           |
| ----------------------------- | ----------------------------------------- | ---------------------------------- |
| `none`, `public`, `anonymous` | the contract asserts the endpoint is open | fires                              |
| any other value               | an auth mode is declared                  | silent                             |
| `unknown`, or absent          | nobody extracted an auth mode             | **silent, and reported as a note** |

An unknown auth mode is not evidence of no auth; treating it as such would turn every unannotated endpoint into a critical finding (`detectors/x6-pii-unauthenticated.ts:17-23`). Tests: declared mode is silent (`detectors/x6.test.ts:65-68`); absent mode is silent and produces exactly one note matching "declare no auth mode" and `unknown, not "no auth"` (`:70-77`); `pii=none` is silent (`:79-81`); no PII classification at all is silent (`:83-85`).

Also silent when the column has `piiProvenance: LLM_SUGGESTED` (weight 0, `props.ts:107-110`), when no path reaches a query, and when any endpoint is not an extracted fact or the path uses an `LLM_SUGGESTED` edge (`graph.ts:59-66`).

## Severity and confidence

Declared `critical` (`detectors/x6-pii-unauthenticated.ts:119`). Confidence is the product of the join confidence to the symbol, the `QUERIES` edge (1 for a fact edge), and the PII weight (`detectors/x6-pii-unauthenticated.ts:99`). Because `critical` needs 0.9 or more (`detector.ts:64-69`):

- All hops `EXTRACTED` and an exact-name PII verdict (confidence 0.9, `packages/extract-data/src/pii.ts:263`) gives exactly 0.9: still `critical`.
- A non-exact PII verdict (0.75, `pii.ts:263`) reports `high`; a column-comment verdict (0.6, `pii.ts:275`) reports `medium`.
- An inferred `IMPLEMENTED_BY` at 0.8 reports the same facts as `high`, at 0.55 as `medium`, at 0.2 not at all. Tests: `severity.test.ts:107-144`.

The label is itself an inference: `extract-data` marks every non-`none` verdict `piiProvenance: 'INFERRED'` (`packages/extract-data/src/emit.ts:187-189`) and the detector prices it in, so a guessed label cannot by itself raise a critical finding above its confidence.

## Controls

- **Declared versus unknown auth** (above), with a note for the unknown case (`detectors/x6-pii-unauthenticated.ts:126-144`).
- **The PII weight is a multiplier**, not a flag (`props.ts:107-114`).
- **Bounded call depth**: handler plus at most two `CALLS` hops (`joins.ts:41-45`).
- **Column names, when present, narrow the match** (`detectors/x6-pii-unauthenticated.ts:94-98`).

## Example

`fixtures.ts` (`x6`): a public operation, its route handler and handler symbol, and a query against a table with a PII column:

```ts
{ kind: 'Operation', name: 'GET /profile', canonical: 'openapi.publicApi#get:/profile',
  props: { auth, method: 'GET', path: '/profile' } },
{ kind: 'Column', name: 'ssn', canonical: 'db.public.people.ssn', props: { type: 'text', pii: 'high' } },
{ kind: 'IMPLEMENTED_BY', src: 'openapi.publicApi#get:/profile', dst: 'route:GET:/profile' },
{ kind: 'HANDLES_ROUTE', src: 'src/routes/profile.ts#getProfile', dst: 'route:GET:/profile' },
{ kind: 'QUERIES', src: 'src/routes/profile.ts#getProfile', dst: 'db.public.people', props: { writes: false } }
```

With `auth = 'none'` it fires (`FIXTURES.X6_PII_UNAUTHENTICATED.firing`): "GET /profile declares auth "none" and reaches people.ssn", confidence 1, severity `critical`, via `IMPLEMENTED_BY, HANDLES_ROUTE, QUERIES, CONTAINS`. With `'session'` (`FIXTURES.X6_PII_UNAUTHENTICATED.clean`, "the operation declares auth "session"") it does not.

Tests: `meta.test.ts:42` (`X6_PII_UNAUTHENTICATED > fires: GET /profile declares auth "none" and reaches people.ssn`) and `meta.test.ts:72` (`X6_PII_UNAUTHENTICATED > does not fire once the operation declares auth "session"`).

## How UNKNOWN arises

Two different things, which must not be confused.

1. **Scope UNKNOWN.** If `contracts`, `code.ts`, `data` or `infer-join` is not `PASS`, the detector is not run and reports UNKNOWN (`runner.ts:93-113`).
2. **Unevaluated operations.** Operations with no extracted auth mode are skipped and counted in a note on the detector's report (the `notes` function of `detectors/x6-pii-unauthenticated.ts`; the runner attaches it to the detector's report). This is not an UNKNOWN outcome. `seamline check` forwards the note as `detectorNotes` (`packages/cli/src/wiring.ts`) and prints it under NOT EVALUATED (`packages/cli/src/commands/check.ts`), so the blind spot is visible in the CLI output as well as to a library caller of `runDetectors`. The MCP `contradictions` tool does not surface detector notes.

## Current status

**Fires.** Every link of the path is emitted by a shipped extractor:

| Link                                                             | Emitted by                                                                                                      |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `Operation.authMode` (`none`, `optional`, `required`, `unknown`) | `packages/extract-contracts/src/emit.ts:111`, mode derived at `packages/extract-contracts/src/openapi.ts:41-77` |
| `IMPLEMENTED_BY` Operation to RouteHandler                       | `packages/extract-contracts/src/extract.ts:331-339`                                                             |
| `HANDLES_ROUTE` Symbol to RouteHandler                           | `packages/extract-code-ts/src/relations.ts:331`, `:397`                                                         |
| `CALLS`                                                          | `extract-code-ts`                                                                                               |
| `QUERIES` Symbol to Table                                        | `packages/extract-code-ts/src/relations.ts` (`emitQueries`), folded in `queries.ts`                             |
| `Column.pii`, `piiProvenance`, `piiConfidence`                   | `packages/extract-data/src/emit.ts:187-189`                                                                     |

Limits that follow from what is emitted, all visible in the code:

- **Only `none` can come from the shipped contract extractor.** It emits `none` for `security: []` or `security: [{}]`, `optional` for `security: [{}, {scheme: []}]` (anonymous admitted), `required`, and `unknown` when no `security` is declared (`openapi.ts:29-40`, `:66-69`). `public` and `anonymous` are accepted by the detector but never emitted. An operation that admits anonymous callers alongside authenticated ones (`optional`) is silent. OpenAPI's own default for an omitted `security` is "no security"; the extractor reports it as `unknown` on purpose (`openapi.ts:36-39`).
- **Reach is table-level.** No `QUERIES` edge carries a `columns` list (write edges carry `insertColumns` and `updateColumns`, which X6 does not read, and a `SELECT` carries none), so every PII column of a queried table counts as reached, including columns the query does not select. The one exception is the edge X6 does not evaluate, below.
- **The `QUERIES` edge is priced as certain.** `extract-code-ts` gives it confidence 0.7 because the table binding is heuristic (`HEURISTIC_CONFIDENCE` in `relations.ts`, `binding: 'unqualified-name'` in `queries.ts`), but its provenance is `EXTRACTED`, and a fact edge contributes 1 to the path (`detectors/x6-pii-unauthenticated.ts`, `effectiveConfidence`; `graph.ts:76-82`).
- **Statements are traced from SQL text in string and template literals** (`emitQueries` in `relations.ts`): a template with substitutions is read from its own literal text, with a placeholder for each substitution. A call into an ORM that never spells SQL has no `QUERIES` edge.

## Edges X6 does not evaluate

A `QUERIES` edge whose `interpolated` prop is true is skipped. `interpolated` is the AND over every statement behind the edge (one edge per symbol and table): it is true only when each of them is raw SQL read from a template literal with at least one substitution. Such an edge says which table a symbol runs SQL against and nothing about which columns, and with no `columns` list X6 would read it as reaching every PII column of that table. Before the classifier read a template's literal text these statements had no edge at all, so skipping them keeps X6 reading exactly what it read then.

- A symbol with a plain `SELECT` and an interpolated `UPDATE` on the same table has one edge with `interpolated` absent, and is read as it always was: the plain statement made the edge.
- The same statement written without a substitution has no `interpolated` prop and is read as before.
- The skip is counted in a detector note ("n query edge(s) were not evaluated; interpolated: n"), only for edges whose table has a PII column, so the blind spot is visible (`seamline check` prints it under NOT EVALUATED, see above).
- The skip is lifted for this kind only by a change that extracts the select list of such a statement into `columns` (X6 already honours `columns`); that needs a cited instance of its own (`docs/design/real-world-inputs.md`, 3.4).

Tests: `detectors/x6.test.ts` ("X6 does not evaluate an edge made only of interpolated templates").

No checked-in test drives X6 through real extraction. A local end-to-end run over a small constructed repository (an OpenAPI operation with `security: []`, an Express handler running `SELECT ssn FROM people`, a `people` table with `ssn` and `email` columns) produced two `critical` findings at confidence 0.9, one for `ssn` and one for `email`, both via `IMPLEMENTED_BY, HANDLES_ROUTE, QUERIES, CONTAINS`.

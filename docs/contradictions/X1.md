# X1_NULLABILITY

Declared severity: high. Required scopes: `data`, `contracts`, `code.ts`, `infer-join`. Status today: can fire; unmeasured (the [index](README.md) defines both terms). Detector: `packages/contradictions/src/detectors/x1-nullability.ts`.

X1 compares `Column.nullable` with a joined response property's `SchemaProperty.nullable`. It fires only when the column states true, the property states false, and response direction is established (`packages/contradictions/src/detectors/x1-nullability.ts:52`). An explicit direction wins; otherwise the anchored OpenAPI response pointer supplies the direction (`packages/contradictions/src/props.ts:131`). A name containing Response is insufficient.

The endpoints must be live EXTRACTED or DECLARED facts. Inferred joins connect them and cap severity: the finding carries the join's confidence, and the declared severity is lowered when that confidence is under the floor for `high` (0.75, from the table in the [index](README.md)); LLM-suggested paths cannot justify findings. Missing nullability never becomes false. Presence and nullability are separate axes.

Requests may validly be stricter than storage. Optional requests need not be inserts, and generic CodeField declarations do not establish stored-row or insert roles. Those former branches are withheld. No shipped fact currently establishes their required roles; [precision boundaries](../design/precision-boundaries.md) explains the coverage loss and default uncertainty.

A failed or unavailable required scope reports UNKNOWN. With no comparable stated response nullability, X1 reports `VALUE_ROLE_UNOBSERVED`, also UNKNOWN. Supported comparisons continue to run alongside withheld branches; detector notes describe those exclusions, and the CLI prints them under NOT EVALUATED.

The synthetic pair is the `x1` builder and the `X1_NULLABILITY` entry of `FIXTURES` in `packages/contradictions/src/fixtures.ts`: a `users.email` column joined by an inferred `BACKED_BY` edge (confidence 0.9) to a response property that states `nullable: false`. It fires while the column is nullable and is clean once the column is `NOT NULL`. Source-level positive and negative controls are in `packages/integration/src/precision-response.test.ts:14`: real extraction, inferred joins and SQLite show a non-nullable response firing, then a nullable response remaining clean while the stricter request stays unchanged. `packages/contradictions/src/detectors/precision.test.ts` covers unsupported shapes and mixed graphs. The standalone-schema demo no longer claims an X1 contradiction.

These controls prove implementation behavior. External-corpus firing and labelled precision must be measured by `pnpm eval`; fixture firing does not count as external validation.

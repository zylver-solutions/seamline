# X2_TYPE

Declared severity: high. Required scopes: `data`, `contracts`, `code.ts`, `infer-join`. Status today: can fire; unmeasured (the [index](README.md) defines both terms). Detector: `packages/contradictions/src/detectors/x2-type.ts`.

X2 compares `Column.type` with a joined `SchemaProperty.type` and format (`packages/contradictions/src/detectors/x2-type.ts:61-64`). Both live endpoints must be EXTRACTED or DECLARED facts; the non-LLM join can be inferred and caps severity: the finding carries the join's confidence, and the declared severity is lowered when that confidence is under the floor for `high` (0.75, from the table in the [index](README.md)). The supported routes are column EXPOSED_AS property and property BACKED_BY column.

Both types must classify before they can disagree. Unknown arrays, unions, generics, user-defined types and unsupported SQL types do not become findings. Specific representation compatibility remains: integer/number, string with uuid/date/datetime/binary, and date/datetime. There is no blanket string-to-number compatibility. Classified string/JSON pairs in either direction are withheld because the declarations do not establish whether serialization mediates between them. They remain incompatible in the shared type table; withholding does not assert compatibility or a working serializer.

Generic CodeField declarations do not establish a stored-row or insert role. Column-to-field and field-to-property comparisons are withheld until authoritative role facts exist. Names, paths and inferred joins cannot supply that proof. See [precision boundaries](../design/precision-boundaries.md).

A required scope that is not PASS reports UNKNOWN. No joined column/property pair with classifiable types reports `VALUE_ROLE_UNOBSERVED`, also UNKNOWN. When every classifiable pair is string/JSON, the reason is `REPRESENTATION_UNOBSERVED`, also UNKNOWN. A mixed graph retains independent findings or known clean comparisons and library notes disclose withheld representations alongside withheld code fields. A supported comparison can still report a finding while library notes describe excluded field comparisons. The CLI prints those notes under NOT EVALUATED.

The synthetic fixture pair (the `x2` builder and the `X2_TYPE` entry of `FIXTURES` in `packages/contradictions/src/fixtures.ts`) compares an integer `users.age` column with a response property reached over an inferred `EXPOSED_AS` edge (confidence 0.9): a property typed string fires, one typed number does not. `packages/contradictions/src/detectors/precision.test.ts` verifies a column/property contradiction survives alongside withheld field shapes, and a boolean UI shape does not create either former field finding. `detectors/controls.test.ts` checks unknown and compatible types. `packages/integration/src/clickhouse-nullability.test.ts` compares real ClickHouse extraction with a stated inline response: the integer/string mismatch fires while aggregate-state types remain unmeasured.

These controls do not establish external precision or recall. Whether X2 fires on an unmodified non-self-authored repository remains an evaluation question. No liveness claim is inferred from fixture-only inputs.

`detectors/x2-representation.test.ts` checks classified types, unchanged compatibility, both directions, direct detection, mixed findings/notes, provenance, tombstones and blocked scopes. `packages/integration/src/precision-representation.test.ts` verifies actual extraction, SQLite facts and a direct inferred join before checking text/object and JSON/string withholding, retained integer/boolean and integer/string findings, and integer/number clean output. The source array property is emitted as `array<string>` and remains unclassified with `VALUE_ROLE_UNOBSERVED`; the test preserves that producer limitation rather than inventing a simpler type. These authored-source controls are not external evaluation.

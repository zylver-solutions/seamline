## What it compares

Declared operations against served route handlers, in both directions (`detectors/x9-contract-drift.ts:1-17`):

- **Declared, unserved.** A contract `Operation` with no `IMPLEMENTED_BY` edge to a `RouteHandler`, on a contract whose other operations are implemented (`detectors/x9-contract-drift.ts:69-108`).
- **Served, undeclared.** A `RouteHandler` with no incoming `IMPLEMENTED_BY` edge from an `Operation`, in a file whose other handlers do map to operations (`detectors/x9-contract-drift.ts:110-158`). The file of a handler is found through the symbol that `HANDLES_ROUTE` it and that symbol's containing `File` (`detectors/x9-contract-drift.ts:164-172`).

## When it fires

- Direction 1: a contract with at least two operations, at least one served and at least one not (`detectors/x9-contract-drift.ts:72`, `:89`). One finding per unserved operation.
- Direction 2: a file with at least two route handlers, at least one declared and at least one not (`detectors/x9-contract-drift.ts:122`, `:139`). One finding per undeclared handler.

## When it must not fire

- **No sibling resolves.** If no operation on a contract resolves to a handler (or no handler in a file maps to an operation), route matching did not work here and reporting every item would report the inference's own failure as the developer's bug (`detectors/x9-contract-drift.ts:89`, `:139`). Tested at `detectors/controls.test.ts:205-207`.
- **Fewer than two operations or handlers** (`detectors/x9-contract-drift.ts:72`, `:122`).
- A handler with no determinable file is skipped (key `''`, `detectors/x9-contract-drift.ts:122`).
- Tombstoned or non-fact nodes, `LLM_SUGGESTED` edges (`graph.ts:59-66`).

## Severity and confidence

Declared `high` (`detectors/x9-contract-drift.ts:56`). Confidence is `resolvedShare * bestSiblingJoin` (`detectors/x9-contract-drift.ts:95`, `:145`), where an `EXTRACTED` edge counts as 1. So severity depends on how much of the contract or file resolves: 3 of 4 gives 0.75 (`high`); 1 of 2 gives 0.5 (`medium`); 1 of 3 gives 0.33 and is dropped. Tested at `detectors/controls.test.ts:209-215`: one of two resolving reports at confidence 0.5 and severity `medium` ("declared high, capped by a half-resolved contract").

## Controls

The sibling control, with the same weight and for the same reason as in [X4](X4.md) (`detectors/x9-contract-drift.ts:10-16`); and the share-weighted confidence, which pushes a mostly-unresolved contract under the floor.

## Example

`fixtures.ts:520-590`: a `petstore` contract with four operations, three route handlers, and `IMPLEMENTED_BY` edges for the three; the fourth gets its handler only in the clean graph:

```ts
{ kind: 'Operation', name: 'POST /pets', canonical: 'openapi.petstore#post:/pets', sourceRef: 'openapi.yaml:34' },
// RouteHandler 'POST /pets' and its IMPLEMENTED_BY edge exist only when implementCreate is true
```

With `implementCreate = false` it fires (`fixtures.ts:722,724`): "petstore declares POST /pets with no route handler while three siblings resolve", via direction 1, confidence 0.75, severity `high`. With `true` (`fixtures.ts:723,725`, "a route handler implements POST /pets") it does not. This fixture exercises direction 1 only. No fixture or control test in this package exercises direction 2, because none of their graphs gives a handler a containing `File`, which is the grouping key (`detectors/x9-contract-drift.ts:111-122`); checked-in integration tests exercise real extraction in direction 2 (below).

Tests: `meta.test.ts:42` (`X9_CONTRACT_DRIFT > fires: petstore declares POST /pets with no route handler while three siblings resolve`), `meta.test.ts:72` (`X9_CONTRACT_DRIFT > does not fire once a route handler implements POST /pets`), and the controls at `detectors/controls.test.ts:173-215`.

## How UNKNOWN arises

If `contracts`, `code.ts` or `infer-join` is not PASS, X9 reports UNKNOWN (`runner.ts:95-112`). Its `absenceOfCode` gate also withholds both directions while workspace packages are unread (`detectors/x9-contract-drift.ts:58`, `runner.ts:115-132`; `incomplete-code.test.ts`).

Even with PASS scopes, X9's `unknownWhen` gate refuses missing, invalid, or positive `unreadStructuredDocuments` counts on fact Contracts or Operations (`detectors/x9-contract-drift.ts:43-51,61-65`). An unread document could contain the operation that would disprove a served-but-undeclared claim. Direct detection refuses the same conclusion (`detector.ts:204-209`). Withholding coverage props cannot turn uncertainty into a finding.

Before profile projection, incomplete raw coverage makes the projected `contracts` scope UNAVAILABLE, including when the profile hides the entire current witness and leaves older operations stamped zero. Reused live views recheck current coverage (`packages/core/src/security/export-policy.ts:616-626,655-661`). Source-view uncertainty with PASS scopes has empty `blockedScopes`; projected-view uncertainty names `contracts` as the blocking scope.

Tests: `detectors/controls.test.ts:217-254`, `unknown-when.test.ts`, `packages/integration/src/partial-contracts.test.ts:492-524`, and `packages/core/src/security/export-policy.test.ts:565-604`. A fully measured contract or file where no sibling resolves remains silent rather than UNKNOWN.

## Current status

**Fires in direction 2 only; direction 1 cannot fire on real extraction.**

- **Direction 1 is unreachable.** `extract-contracts` emits an `IMPLEMENTED_BY` edge from every `Operation` to a `RouteHandler` keyed by method and path, unconditionally, "not gated on a vendor extension being present" (`packages/extract-contracts/src/extract.ts:338-352`). Every operation therefore looks served, `unserved` is always empty, and the detector exits at `detectors/x9-contract-drift.ts:89`. The edge records that a handler _identity_ exists, not that code serves it; the handler node is only backed by code when `extract-code-ts` emits the same `RouteHandler` id. This matches the README ("X9 detects only one of its two directions").
- **Direction 2 is live.** `extract-code-ts` emits `RouteHandler` nodes and `HANDLES_ROUTE` edges for router-style calls with server receiver evidence and for supported decorator routes (`packages/extract-code-ts/src/relations.ts:331-352,402-419,438-456`; receiver rules for router-style calls in `packages/extract-code-ts/src/receiver.ts:1-40`), and `extract-contracts` supplies the declared side. A route in code whose method and path match no declared operation has no incoming `IMPLEMENTED_BY` from an `Operation`.

Direction 2 reports only inside a file where at least one route is declared and at least two are served, so it reads "this file's routes are partly in the contract", and its confidence is the declared share of the file's routes. A route file wholly outside the contract is silent.

Checked-in real-extraction tests cover direction 2 and uncertainty: `packages/integration/src/partial-contracts.test.ts:469-524` creates three served routes with two declared operations, checks the one undeclared-route finding, then verifies that unread structured input and a hidden current witness force UNKNOWN. The same suite proves that an unsupported Zod-only file cannot hide operations and does not suppress the otherwise observable direction-2 finding.
